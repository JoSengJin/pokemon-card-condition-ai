```text
머리말: "제안서 초안이다. 사람 재판정 요청이 아니며 승인 전에는 어떤 요청·화면 생성·구역 선정 실행·수집도 하지 않는다. 새 규칙이나 승인을 만들지 않는다. 기존 규칙과 부딪히면 기존 규칙이 우선한다. 정확도 변화 없음."
표기: 새 수치·문턱에는 모두 "제안"과 출처(파일·절·행)를 단다. 이미 발효된 값은 "기존 값"으로 구분한다. 출처가 없으면 "근거 없음"으로 쓰고, 값은 사용자가 정할 `<사람>`으로 둔다. 계산한 값은 식과 명령을 적는다.

1. 목적과 줄 수 있는 것·없는 것. 지식 문서 §4대로, 자기 일치도는 한계선만 준다. 정답이 맞는지(타당도)와 일관된 엄격·느슨 버릇은 못 잰다. "정확도"가 아니라 "그 판정과의 일치율"로 쓴다.

2. 대상 칸과 기준 정본. 칸은 `<사람>`이고 제안은 모서리다(오류 14장과 기존 재판정이 모서리이고 정본이 있다는 이유). LABELING_PROTOCOL.md의 "기준 정본" 절과 해당 칸 절만 가리킨다. 모서리 기준은 2026-11-24 문구로 바뀌었으므로 "다시 잴 대상"이다.

3. 무엇을 두 번 재는가(핵심). 현행 기준·같은 화면·같은 크롭으로 1차와 2차를 모두 새로 받는 설계를 제안한다. 과거 라벨은 기준·화면이 달랐거나 "버전 미상"이라 1차로 쓰지 않는다. 2026-11-23·24 W1 재판정도 기준 문구 개정 전후가 섞일 수 있고 주체 확인 문장이 없어 1차로 쓰지 않는다. 두 번 받는 사용자 부담을 밝힌다. 완료 라벨 재요청 금지에 걸리므로 비율·구역 수 승인이 있어야 한다.

4. 선행 값의 지위(표). W1 B 45구역(43/45, kappa 0.909, 주체 확인 문장 없음, 기억 효과·쉬운 구역 편향)은 참고다. 2026-11-21 24쌍 kappa 0.595는 1차 AI 서브에이전트·2차 주체 미확인이라 자기 일치도가 아니다. 통합 전 측정은 소급하지 않으므로 정식 값은 "미측정"이다. 어느 것도 이번 결과와 합치지 않는다.

5. 최소 분모. 기존 값은 확정 쌍 30(LABELING_PROTOCOL.md, 승인 기록은 quality-threshold-proposal-20261125.md 머리)이다. 확정 쌍은 1차와 2차가 모두 정상 또는 결함인 구역이다. 이유는 선례와 구간 폭이며, 불일치 0/30이어도 정확 양측 95% 상한이 11.6%라는 지식 문서 값을 쓴다. 30은 충분하다는 뜻이 아니라 "미측정"을 벗는 최소라고 적는다. 시작 구역 수는 `<사람>`이며 판단 불가로 줄어들 여유를 식(시작 수 × 예상 확정 비율)으로만 보인다. AI 판정의 판단 불가 41.7%는 예상치로 쓰지 않는다. 시작 뒤 결과를 보고 구역을 더하지 않는다.

6. 구역 선정 규칙. 두 층을 섞는다.
   - 주 층: 모델 점수·오답 여부·이전 재판정 결과와 무관하게 사전 고정 시드로 뽑은 구역. 모집단과 제외 조건을 적는다. 봉인·독립 자료는 제외하고, 같은 실물 카드가 겹치지 않게 한다. 이전 라벨로 층을 나눌지와 그 비율은 `<사람>`이며, 나누면 모집단 비율과 달라진다고 적는다.
   - 보조 층(오류 구역): corner-error14-breakdown-20261124.md에 이미 고정된 오류 구역. 점수로 고르거나 순위를 매기지 않는다. 다만 오류 여부 자체가 모델 출력에서 나온 선택이므로 e 추정과 주 지표에서 빼고 건수만 보고한다. 이 결과로 정답표를 고치지 않는다(지식 문서 §2 "불일치 건만 재판정").
   - 최소 분모 30은 주 층만으로 채운다. 화면에는 중립 번호만 보이고 층·이전 답·점수·카드 ID는 숨긴다. 선택 규칙·시드·모집단 파일 해시는 사진·점수를 보기 전에 고정한다. 이미 오류 구역을 알고 있는 관찰자라는 선행 노출을 밝힌다. 실제 목록은 이 문서에서 만들지 않는다.

7. 간격·순서·눈가림. 간격은 `<사람>`, 제안은 2주다. 지식 문서의 "2주 간격 50항목 같은 설계가 쓰였다(하)"만 근거이며 권고 수치가 아니라고 적는다. 2차는 다른 시드로 순서를 섞고 번호를 새로 매긴다. 이전 답을 숨기고 예측 미리 채우기는 하지 않는다. 확대 조건·화면·기준 문구 버전·크롭 해시는 두 회차가 같아야 한다. 회차별 제출 시각을 기록하고, 간격을 어기면 사전 규칙 이탈로 표시해 정식 값으로 쓰지 않는다. 화면을 만들면 label-screen-round-trip 시험이 먼저다.

8. 판정 주체. 회차마다 "내가 직접 판정했다"는 사용자 확인 문장을 함께 저장한다. 한 회차라도 없으면 "주체 미확인"이며 목표·경고 판정은 참고로만 쓴다. AI 답과 다른 사람 답은 섞지 않는다.

9. 판단 불가와 분모. 판단 불가·미확인을 정상·결함으로 채우지 않는다. 시작 수, 회차별 판단 불가·미확인 수, 한 회차만 확정된 수, 확정 쌍을 모두 보고한다. 판단 불가 제외가 쉬운 구역 쪽으로 치우치게 한다고 적고, 3분류 일치도는 보조로 둔다. 두 답은 병합하지 않으며 라벨을 바꾸지 않는다. 엇갈린 구역은 "불확실"로만 둔다.

10. 결과 지표(결과 전 고정).
   - 확정 쌍 일치율 k/n과 윌슨 95% 구간, 2×2 혼동표와 3분류 표, 이진 kappa와 95% 구간. kappa 구간은 실물 카드 단위 부트스트랩을 제안하되 반복 수·시드를 고정하고, 소표본에서 덜 믿을 만하다는 한계를 적는다(w1 선례, 지식 문서 §1). kappa만 따로 보고하지 않는다.
   - 쏠린 불일치: b=1차 정상→2차 결함, c=1차 결함→2차 정상. b, c, b/(b+c)와 정확 이항 양측 검정을 쓴다. b+c=0이면 비율은 "해당 없음". 이것은 회차 사이 기준 이동의 신호이며, 일관된 엄격·느슨 버릇의 크기가 아니다. 유의하지 않음은 쏠림 없음의 증명이 아니다.
   - 기존 규칙의 "한쪽으로 쏠리면 미측정"은 값의 쏠림에 대한 수치 정의가 없다. 조작 정의를 하나 제안하고 `<사람>`으로 둔다. 불일치 방향의 쏠림과 구분한다.

11. 결과를 보기 전에 고정할 결정 규칙.
   (a) e 추정: d=불일치 쌍/확정 쌍, 1차·2차 오류가 독립이고 같은 확률로 양방향에 일어난다고 가정하면 d=2e(1-e), e=(1-sqrt(1-2d))/2. 저장소 선례는 score.py의 flip이다. d 구간의 양 끝을 변환하고, d≥0.5면 추정하지 않는다. corner-blind-rejudge-20261121.md 17행은 거의 우연 수준 일치에 이 모형이 맞지 않는다고 적었다.
   (b) 한계: 두 번 함께 틀리는 버릇·기억 효과는 e를 과소 추정하게 할 수 있다. 정상·결함 쪽 오류율이 다르면 두 회차만으로 따로 식별되지 않는다. 현행 기준에서 잰 e를 다른 기준의 과거 평가 라벨에 그대로 옮길 수 없다. Lam & Stork 범위의 e는 정답 대비 오류율이고 자기 일치도의 e는 가정 아래 대용치다. 모델이 같은 판정자의 라벨로 학습돼 독립 가정도 의심된다.
   (c) 구분할 수 없는 폭: 구역 N개 평가에서 겉보기 오류 수의 ±(e 상한 × N)을 "제안된 참고 폭"으로만 쓴다. 겉보기 총수의 폭과 두 모델의 짝지은 차이는 다르다. 카드 점수는 구역 최댓값이므로 구역 폭을 카드 장수로 바꾸는 방법이 정해지지 않으면 카드 폭은 "미측정"이다. 이 폭을 넘었다는 이유만으로 개선이라고 부르지 않는다.
   (d) 다음 행동 표: 위에서부터 먼저 맞는 한 행만 쓰고 경계값이 빈틈없이 나뉘게 한다.
      1) 주체 미확인·간격 이탈·화면이나 기준 버전 불일치 → 정식 값 없음, 이유 보고
      2) 확정 쌍 30 미만·kappa 정의 불가·값 쏠림 → 미측정, 자료 추가는 새 승인
      3) 사전 고정한 불일치 방향 기준 초과 → 기준 이동 의심, 기준 문구·제시 방식 점검 제안, e를 쓰지 않음
      4) kappa 0.60 미만 → 모델 가설 전에 기준 문구·제시 방식 점검(기존 규칙)
      5) 0.60 이상 0.80 미만 → 경고선 위·목표선 아래로 보고, e 참고 폭과 세 장수를 다시 씀
      6) 0.80 이상 → 목표선 충족으로 보고, 기억·쉬운 구역·타당도 한계를 유지
      판정은 기존 값대로 점추정으로 하고 95% 구간을 함께 적는다. 0.80·0.60은 관례이며 이 프로젝트에서 잰 값이 아니다. 3)의 문턱은 `<사람>`이다. 어느 행도 실험·라벨 변경·재요청을 자동 승인하지 않는다. 결과를 본 뒤 바꾸지 않는다.

12. 판별 가능성의 세 장수. ① 겨냥 묶음 장수=0(입력 경로 진단에서 원인 확인 항목 없음)이라고 출처와 함께 적되, 이는 그 진단에 한정되고 다른 가설에서는 "미측정"이다. ② 필요 개선=오탐 9→7의 2장(corner-input-path-diagnosis-20261125.md 7절의 출처 재확인). ③ 라벨 흔들림=미측정. ②는 카드, ③은 구역이라 단위가 다르다. 이 측정은 라벨 진단이며 모델 가설을 내지 않는다. 같은 규칙은 새 라벨을 요청할 때 "몇 장을 보고 오류 몇 개 이하면 채택"과 두 위험을 미리 적으라고 한다. 정답 대비 오류를 세는 채택 시험이 아니므로 값을 지어내지 말고, 이 측정에 맞게 "목표선 판정이 잘못 통과·잘못 미달할 위험"을 정성적으로 적고 확률은 미측정으로 둔다.

결론 한 줄(개발 진척률 변화 없음·정확도 변화 없음 포함) / 커밋 전체 SHA 40자 / 변경 파일·핵심 내용 / 구조: 코드 변경 없음 / 검사 명령·출력·종료 코드·대상 SHA / `<사람>` 목록 / 원문과 프롬프트의 차이 / 읽은 범위 / 적용 규칙·못 지킨 규칙 / 미검증 / 위험 / 롤백 / HTML 없음과 이유 / 에튜 1~2개(원리→이번에 쓴 이유→작은 예). 제안 승인이나 재판정을 사용자에게 직접 요청하지 않는다.
```

## 관리자 인수 확인 (참고)
- 두 작업 모두 코드 변경이 없어 함수 수·호출 깊이는 해당 없음, HTML 보고 없음(모델 평가 아님), 정확도 변화 없음.
- 세션 완료 뒤 관리자가 `git diff --stat <base> <tip>`, `git show <tip>:<파일> | wc -lc`, 허용 파일 대조, 절대경로 검사를 직접 한다. 세션 보고를 그대로 믿지 않는다.
- 롤백: 이 계약 문서의 커밋 revert(실행 전).
