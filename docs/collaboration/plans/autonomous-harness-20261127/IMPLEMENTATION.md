## 0. 착수 조건

- [DECISIONS.md](DECISIONS.md) 2-1의 D-1~D-4가 사용자 원문으로 확정되어야 한다. D-1(AGENTS.md 하네스 절)이 없으면 Supervisor 상시 실행·자동 재개가 현행 규칙 위반이다.
- 구현은 AGENTS.md·`PAIR_CODING.md`(함수 수·호출 깊이 제한, 파일 소유권)·`docs/AGENT_START.md`를 따른다. 모델·worker 수정은 `./develop -- <명령>`, 새 실험은 `./experiment --plan … -- …`로만 한다.
- 실제 학습·모델 비교·사진 추론·라벨 수정은 기본 checkout의 단일 담당자만 한다. 구현 worktree에서는 실행하지 않는다.
- main 통합·push는 고지 후 사용자 승인을 받는다.

## 3. 최종 완료 증명 (실제 실행)

사용자 완료 기준: "사용자의 추가 지시 없이 개발, 자동 라벨링, 학습, 평가, 다음 가설 생성이 반복되고, 단기·주간 사용량 한도 초기화 이후 자동으로 개발을 이어가는 것을 실제 실행으로 증명".

| # | 증명할 것 | 방법 | 판정 근거 |
|---|---|---|---|
| T1 | 사람 지시 없이 실험 → 분석 → 다음 가설 → Silver → 학습 → 평가가 **2회전** 반복 | 실제 운영 | 장부의 작업 연쇄, 사용자 메시지 없음 |
| T2 | 단기 한도 도달 → Python 계속 → 초기화 뒤 자동 재개 | 실제 한도 | 장부의 `RATE_LIMITED_SHORT` → 재개 시각 |
| T3 | `--resume` 실패 → 저장 상태로 새 세션 재개 | 세션 ID를 일부러 무효화 | 장부의 새 세션 ID와 이어진 작업 |
| T4 | 주간 한도 초기화 뒤 자동 재개 | 일부러 만들 수 없으므로 실제 발생을 기다림 | 장부의 `RATE_LIMITED_WEEKLY` → 재개 |
| T5 | 감사 실패 시 해당 Silver를 쓴 모델과 후속 모델 무효화·복원 | 합성 실패 주입 | 레지스트리 계보와 Champion 포인터 |
| T6 | 한도 중 앱 푸시와 중단 명령 | 실측 | 수신·중단 여부. 안 되면 원격 제어 한계로 기록 |
| T7 | 작업별 실제 사용 모델·effort가 라우팅 정책과 일치 | 장부와 정책 문서 대조 | D-4 문서 필요 |

T1~T7 증거는 `artifacts/harness-proof-<날짜>/`에 장부 발췌·명령·로그와 함께 남기고, [HTML_REPORTING.md](../../HTML_REPORTING.md)에 따라 휴대폰에서 볼 HTML로 보고한다. 이 증명은 하네스 동작의 증명이며 모델 정확도 개선의 증명이 아니다.
