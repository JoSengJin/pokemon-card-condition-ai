## 3. 새 자료부터 기록할 라벨 이력 스키마 (H1 대응)
기존 `corners`(정상/결함/미확인 문자열 맵)와 제출 파일 검증은 그대로 두고, 같은 행에 `corner_meta`를 추가한다.
```
corner_meta: { <area>: { pass: "first" | "refill", confidence: 1|2|3 (확실/보통/애매), unknown_reason: null | 사유 } } × 4구역
사유(기존 사유 표): 흐림·저해상도·초점 / 슬리브·탑로더·비닐 반사 / 직선 테두리·후광·스캔 번짐·인쇄 광선과 구분 불가 / 잘림·비스듬한 각도 / 그림자·스탠드·가림 / 기타
```
- `unknown_reason`은 칸이 미확인일 때만 필수(아니면 null). `pass: refill`은 기존 판정이 미확인이던 칸을 별도 제출에서 채울 때만 쓰며, 첫 제출 기록은 덮어쓰지 않고 이력으로 남긴다. 새 수집 라운드는 미확인 포함 카드를 부적격으로 두는 현행 규칙이라 refill이 생기지 않는 것이 기본이다.
- 정상 풀 구분 집계: `first-pass-all-confirmed`(네 칸 모두 첫 제출 확정) / `refilled`(한 칸 이상 refill). 결과 보고는 두 층의 분모를 따로 공개한다. 검증·집계 `pool_strata.py`(자체 점검 통과, 실데이터 없음).
- 검토 화면(`page.js`·`build-page.py`·`receive-answers.py`) 수정은 새 후보가 생길 때 같은 복사본에서 한다. 지금은 후보가 없어 새 사람 입력 화면을 만들지 않았다(사용자 입력 요청 없음).
