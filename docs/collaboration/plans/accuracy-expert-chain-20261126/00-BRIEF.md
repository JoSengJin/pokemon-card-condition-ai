# 정확도 향상 전문가 릴레이 — 공통 지시 (2026-11-26)

목표: 카드 상태 분석 AI 모델의 정확도(같은 평가 자료·같은 분모에서 결함 누락·오탐 감소)를 높이기 위해 해야 할 일 목록과 설계를 만든다.
사용자 결정: 정확도가 최우선, 진척률 점수 올리기는 후순위. 목표 정답은 사람 판정(AI 판정은 분리).

## 진행 방식
- 분야별 담당이 차례로 일한다. 앞 담당의 파일(이 폴더의 01~, 번호순)을 먼저 모두 읽고, 동의·반박·보완을 근거와 함께 이어 쓴다.
- 역할극 금지. 실제 그 분야 실무자가 하는 일(자료 열람, 수치 집계, 코드·기록 대조, 설계 산출)을 하고 결과만 적는다.
- 모든 주장에 근거(파일 경로:줄, 기록 경로, 직접 집계한 수치와 명령)를 붙인다. 모르면 "미확인"으로 적는다. 추정은 "가정"으로 표시한다.

## 반드시 지킬 경계 (AGENTS.md 요약, 원문 우선)
- 먼저 AGENTS.md 전체와 docs/AGENT_START.md를 읽는다. 해당 분야 원문(LABELING_PROTOCOL.md, COMMON_EXPERIMENT_RECORDS.md, OBSERVATION_CONSENSUS_20261011.md, docs/agent/QUALITY_RULES.md, docs/knowledge/accuracy-evidence-methods-20261125.md 등)을 필요한 만큼 읽는다.
- 읽기 전용 조사 + 설계 문서 작성만 한다. 금지: 학습, 모델 비교 실행, 사진 추론, 라벨 수정, `./develop`, `./experiment`, `./review`, Gemini·Codex 등 외부 AI 호출, git commit/push, 이 폴더 밖 파일 수정.
- 기존 기록 파일을 읽고 python으로 세는 정도의 읽기 전용 집계는 허용(입력 파일 변경 금지, 임시 파일은 /tmp 아닌 자신의 파일 안 표나 stdout으로).
- 완료 라벨 재요청 제안 금지, 미확인을 정상/결함으로 추정 금지, 모델 오답을 이유로 사람 정답 변경 금지.
- 이미 실패한 가설을 같은 자료로 재시도하자는 제안 금지(같은 자료 반복 통과는 "우연 가능"). 과거 미채택 후보는 기록을 찾아 확인한다.

## 각 담당의 산출 파일 형식 (NN-분야.md)
1. 이 분야에서 실제로 한 일(읽은 파일, 실행한 집계 명령)
2. 발견(근거 포함) — 정확도를 막는 원인 위주
3. 해야 할 일 목록: 항목마다 기대 효과(누락/오탐 중 무엇), 필요한 입력, 사람 의존 여부, 선행 조건, 우선순위(상/중/하)
4. 설계: 가장 우선인 1~3개 항목의 구체 설계(데이터·절차·판정 기준 수치를 사전에 고정, 변경 변수 하나)
5. 앞 담당 의견에 대한 반박/보완
6. 다음 담당에게 넘기는 질문·미확인 사항
