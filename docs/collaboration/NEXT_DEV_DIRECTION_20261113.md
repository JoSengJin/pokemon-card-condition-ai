# 다음 개발 세션용 방향 (Claude 판단, 2026-11-13)

사용자가 "다른 세션에서 개발"하도록 Claude 판단으로 정리를 위임했다. **승인된 실험이 아니다.** 새 학습·추론·Gemini/Codex 호출·라벨/게이트 변경은 사용자 승인 후에만. 개발 진척률 v1.13 78/100 불변.

## 1. 진단 요약 (근거: reports/independent-judgment-*.md, ai-vs-human-defect-gap-diag-20261113.md)
- 병목은 표현이 아니라 **정답 정의와 게이트의 불일치**다. 표현 학습 6가설 탈락, 임계 보정은 FP를 못 줄임(오류가 순위 오류), 같은 사람 라벨 재현성 낮음.
- 사람 라벨은 확대 기준이고 문턱 A(확대 없음, AI 판정자) 합의와 다르다. 사용자가 제품 범위를 **A(기본 표시에서 보이는 자국)** 로 위임 결정(독립-판정 결정 기록). 사람 개입은 불가.
- **새 사실(탐색, AI 합의 기준, 사람 검증 아님)**: 저장 점수 vs 문턱 A 합의 결함에 대한 칸 크기 가중 AUC **0.943**(그룹 부트스트랩 95% 0.897~0.975, n=125 판정 가능, 결함 23). 사람 target을 점수로 쓴 같은 계산은 0.877. 즉 모델 점수는 A에서 보이는 결함을 잘 서열화한다. 가중하지 않은 AUC는 0.743(오류 칸 과대표집 때문). 탐색 160곳에 파일럿 40곳이 포함돼 독립 표본이 아니고 판단불가 35곳 제외.
- 칸별 A 합의 결함: TN 0/33, FP 4/33(12%), FN 6/31(19%), TP 13/28(46%). 해석(추정): **FP 칸은 A 기준에서도 대부분 정상이라 실제 오경보 가능성이 크고, FN 칸의 다수는 A에서 보이지 않는 자국이라 모델이 못 잡는 것이 당연할 수 있다.** 확정 아님(n 작음, AI 판정).

## 2. 방향 (우선순위, 모두 한 번에 변수 하나)
**P0. 평가·제품 출력 재정의 제안(사용자 결정, 개발은 분석만)**: 이진 게이트 대신 "점검 우선순위(순위)" 출력과 예산 지표(상위 k곳 재현율·정밀도, 사진당 순위)를 기존 저장 점수·target으로 계산하는 분석 스크립트(`tools/diagnostics/<새폴더>/`, 새 추론 없음). 게이트 FN≤67/370, FP≤112/1406, AUC +0.03은 **변경하지 않고** 대안 지표를 병기해 사용자에게 제시만 한다.
**P1. 모델 가설 후보(승인 후 `./experiment`)**
 1. 입력 스케일: 사람은 확대해서 판정했는데 크롭이 작다(234~384px). 모델이 구역을 어떤 해상도로 보는지 코드로 확인하고(추정이 아니라 읽기), 스케일 단일 변수(예: 고해상도 패치 병행)를 가설로 사전 등록. 6개 표현 가설 중 중복 여부 확인 필수(과거 실패 가설 재시도 금지).
 2. FP 칸 집중: A 합의에서 정상인 FP 칸(167곳)의 공통 패턴(카드 밖·가장자리·반사 등)을 저장 기록으로 분류하는 진단. 가설 하나로 압축.
 3. 소음 강건 학습: 같은 사람 반복 판정이 있는 구역(구역 평가 100·심각도 60 등, 약 230)의 일치/불일치를 가중치로 쓰는 안. 표본이 작아 효과 미확인, 후순위.
**P2. A 기준 target 재정의(사람 개입 불가 → 보류)**: AI 합의를 학습 라벨로 쓰는 것은 같은 계열 오류·독립 검증 불가 위험이 커서 **사용자 승인 없이 하지 않는다.** 평가 보조 신호로만 사용.

## 3. 지킬 규칙
- `AGENTS.md`·`PAIR_CODING.md`: 학습·사진 추론·라벨 수정은 기본 checkout 단일 담당, 모델·worker 수정은 `./develop -- <명령>`, 새 실험은 `./experiment --plan <계획.json> -- <실행 명령>`, 가설 ID·단일 변수·대조 경로·사전 수치 기준 명시.
- 변경 전 baseline snapshot, 결과를 본 뒤 기준 변경 금지, 실패·중단은 성능 수치로 쓰지 않음.
- 사람 새 판정 요청 금지. AI 합의는 "사람 검증 아님" 표기. 원본 사진·응답·비밀값 Git 제외.
- 성능을 새로 평가하면 구역별 사람 정답·모델 출력 HTML과 개발 진척률·성과를 먼저 보고(`HTML_REPORTING.md`).
