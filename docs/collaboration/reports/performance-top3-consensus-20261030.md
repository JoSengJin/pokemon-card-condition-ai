# 성능 저하 요인 Top3와 새 방안 합의 — 2026-10-30

**모의 컨설팅이다.** 실제 OpenAI 모델·API를 호출하지 않았다. "이미지 모델 수석개발자"는 Claude가 맡은 역할(페르소나)이며, 아래 발언은 실제 인물·회사의 의견이 아니다. 근거 수치는 이 저장소의 기록에서 확인한 것만 쓴다. 개발 검증이며 독립 시험이 아니다.

## 1. 성능을 떨어뜨리는 가장 큰 요인 Top3

1. **정상(음성) 자료가 적고 출처가 안 맞는다.**
   - 검증 275구역 중 eBay가 96%인데 학습 130단위 중 eBay는 37(정상 14)뿐이다.
   - 3차 실행(20261030T113857-2deb9558): 누락 18/117, 오탐 59/158, AUC 0.804. 이전 실행 AUC는 0.679, 0.493이다.
   - 정상 카드 17장에서도 정상 105구역 중 38개(36%)가 오탐이다. 오류는 카드 54장 중 44장에 흩어져 있다.
2. **"결함 신호"와 "카드 뒷면 디자인·조명"이 분리되지 않는다.**
   - 지금은 고정 DINOv2 패치 특징 + 선형 head이고, 얇은 가장자리 띠를 448px로 확대해 넣는다.
   - 새 배치 g의 정상 면 `4fdbe9…`는 8개 구역 중 6개가 0.75 이상이다. 한 구역의 국소 결함이 아니라 면 전체가 반응하는 모양이다.
3. **정답 신호가 약하고 평가 분모가 작다.**
   - 구역 단위 정답이 부족하고 면 단위 정답은 간접적이며, 사람 라벨 잡음은 측정하지 못했다.
   - 면 단위 정상은 지금 7면(이전 2 + g 5)이라 모델 선택이 잡음에 흔들린다.

**요인이 아닌 것으로 본 것:** 상자 기울기. 모서리 펴기는 11면에서 +1면, 새 배치 17면에서 FN 1/12·FP 3/5 동일(0%p)이었다.

## 2. 3회 토론 (모의)

**1회전 — 데이터를 늘릴까, 표현을 바꿀까**
- 이미지 수석(모의): 정상 자료는 사람이 모아야 해서 느립니다. 뒷면은 포켓몬 카드 전체가 같은 인쇄 디자인입니다. 정상만으로 "정상 패치 은행"을 만들고 거기서 멀면 이상으로 보는 방식(PatchCore형 이상 탐지)이면 결함 라벨 없이도 디자인·조명 차이를 흡수합니다.
- Claude: 지금 head는 정상/결함 둘 다 학습하는데 정상이 적습니다. 정상만 쓰는 방식이 정보 손실이 적습니다. 다만 뒷면 디자인이 시대·언어별로 다릅니다.
- 쟁점: 디자인 차이. 합의: 은행을 학습 정상 단위로만 만들고, 디자인별 분리는 이번엔 하지 않는다(변수 하나).

**2회전 — 임계값과 평가를 어떻게 고정하나**
- 이미지 수석(모의): 이상 점수는 단위가 달라서 val을 보고 임계값을 정하면 안 됩니다. 학습 정상끼리 그룹 교차(한 그룹 빼고 은행 구성)로 점수 분포를 얻고 임계값을 미리 규칙으로 고정하세요.
- Claude: 같은 검증 275구역과 3차 실행 점수를 기준으로 쓰면 비교가 바로 됩니다. AUC는 임계값과 무관해서 보조가 아니라 1차 지표로 같이 봅니다.
- 쟁점: 새 방식의 점수를 0~1로 어떻게 바꾸나. 합의: 그룹 교차 정상 점수의 90분위를 임계값으로, 표준편차를 척도로 하는 단조 변환(AUC 불변). 검증 점수를 본 뒤 바꾸지 않는다.

**3회전 — 성공 기준과 위험**
- 이미지 수석(모의): 정상만 보는 방식은 "정상인데 처음 보는 디자인"을 오탐하고, 미세 결함은 패치 거리에 안 잡힐 수 있습니다. 그래서 실패해도 정보가 되도록 기준을 미리 정하세요.
- Claude: 기준은 3차 실행과 같은 검증에서 AUC가 +0.05 이상, 그리고 누락 18 이하·오탐 59 이하입니다.
- 합의: 기준 미달이면 채택하지 않고, 학습 head와 이상 점수를 합치는 후속 가설은 이 결과를 본 뒤 별도 계획으로 세운다.

## 4. 리스크·롤백

- 디자인이 다른 정상이 오탐으로 늘 수 있다(2회전 쟁점). 은행 크기가 작아 그룹 교차 분포가 불안정할 수 있다.
