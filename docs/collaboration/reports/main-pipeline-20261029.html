미검증·리스크·남은 확인(실제 CLI 최초 시험 전)

  • 실제 CLI 미검증: codex exec --sandbox read-only/claude --print --permission-mode plan이 입력 폴더의 파일을 읽고 shasum -a 256(diff 해시)을 직접 계산할 수 있는지, 마지막 줄 JSON 출력 규약을 지키는지 확인 필요. 못 하면 확인이 계속 거부되어 파이프라인이 멈춘다(안전 쪽 실패).
  • 의미 검토는 증명되지 않음: diff 해시·변경 파일·메모는 "그 내용에 묶인 증거"일 뿐 모델이 이해했음을 증명하지 못한다. 별도 독립 리뷰(모델) 호출은 연결하지 않았다.
  • 새 행동은 장부 기록 필요: confirm_handoff·push_main(대상=브랜치 이름)을 사용자가 장부에 기록하지 않으면 수행되지 않는다. 기존 AGENTS의 일반 push 상시 승인을 장부로 자동 변환하지 않았다.
  • 연속 처리는 첫 인수 이후에만 켜진다(교대 전 사용자 직접 흐름은 그대로). 직렬화·중복 방지는 프로세스 내부 보장이며 전역 잠금이 아니다. 기존 테스트도 이제 승인된 작업에 자동 단계가 돈다.
  • 구현 에이전트 한도 등 전체 한도(ex.limit) 상황과 실제 한도 문구 형식은 가짜 문구로만 확인.
