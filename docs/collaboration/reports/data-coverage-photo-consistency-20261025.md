# 감사 입력 사진의 단계 간 일관성 — 2026-10-25

개발 진척률 30/100 유지. manifest가 같아도 두 읽기 사이에 사진 픽셀이 바뀌면 이전 해시를 담은 보고서가 생성되는 소프트웨어 결함을 합성 입력으로 재현하고 차단했다.

## 변경 파일과 작동 원리

- `card_condition/point_dataset.py`: 이미 읽은 카드 ID·면별 디코딩 사진 해시를 `input_image_hashes` 메타데이터로 반환한다. patch·라벨·학습 입력·count 계산은 그대로다.
- `card_condition/data_coverage.py`: 첫 읽기와 투영 단계의 사진 해시를 비교하고 다르면 저장 전에 ValueError로 중단한다. 구역 patch가 없는 면도 검사한다.
- `tests/test_data_coverage_photo_consistency.py`: 픽셀 변경·무구역 면 변경의 거절과 동일 픽셀 재인코딩의 허용을 검증한다. 봉인된 test 사진/라벨은 읽지 않는다.
- task 문서와 이 보고서: 소유권·검증·경계 기록.

## 실제 검증

수정 전 신규 3검사 중 2개 실패·1개 통과로 두 결함 경로를 재현했다. 수정 후 기존 44개, 신규 3개, 기존 point_comparison 1개 총 48개가 통과했다. 로그는 `artifacts/data-coverage-photo-consistency-20261025T011643/before-tests.log`, `tests.log`, 판정은 `verification.json`이다.

실제 개발/live manifest를 새 출력 경로로 재감사한 결과, 직전 통합 검증의 두 보고서와 전체 JSON이 동일했다. manifest SHA도 불변이다. 기존 라벨·분모·정답을 바꾸지 않았고 실제 사진의 픽셀을 수정하지 않았다. 합성 테스트만 임시 사진을 변경했다.

사진을 추가로 디코딩하거나 모델을 실행하지 않고 기존 두 읽기의 결과만 대조한다. 학습·모델 추론·외부 AI 호출은 0이다. 정확도·속도·일반화 개선은 측정하지 않았다.

## 리스크·미검증·롤백

point_rows 결과에 사진 해시 메타데이터 한 필드가 추가된다. 기존 반환 tuple·patch와 기존 필드의 의미는 유지하며 관련 dataset/comparison 회귀를 통과했다. 모든 외부 소비자의 엄격한 JSON 키 검사를 검사한 것은 아니다.

이 보호는 두 읽기가 서로 다른 디코딩 사진을 사용한 경우를 잡는다. 사진 파일 자체를 잠그지 않으며, 두 번째 읽기 이후 또는 바꿨다가 원복된 모든 변경까지 감지하는 기능은 아니다. 사진 바이트가 달라도 같은 디코딩 픽셀이면 허용한다.

Claude의 원본 출처·정정 이력 감사 파일은 변경하지 않았다. 그 미해결 내용은 별도 결과를 받아 판단한다. 롤백은 진행 중 실행·후속 변경을 확인한 뒤 이 task의 수정 커밋을 `./develop -- git revert <수정 SHA>`로 되돌린다. 원본 데이터·모델 복구는 필요 없다.
