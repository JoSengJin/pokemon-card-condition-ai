익명 콜백 포함 총 함수 노드는 mainApprovals 14, mainHandover 12, mainCheckpoint 16 등 7을 넘는다. 기준이 이름 있는 함수만 세는지 콜백까지 세는지 이 문서만으로 확정할 수 없어, 기준 해석은 현재 메인이 결정해야 한다.

호출 전이: 시작 함수 onMainEnd의 최장 경로는 onMainEnd → ackSession → applyActions → runOne → (runtime) approve → (executor) approve → setStatus → event로 7회(변경 전과 같음). 내 코드 구간 onMainEnd→…→runOne→mainOps는 4회지만, 기존 Executor의 승인·상태 변경 내부가 이어져 4회를 넘는다. 이 초과는 executor.ts 내부 구조에 있어 이번 작업 범위(요청하지 않은 리팩터링 금지)로 해소할 수 없다. 필요한 결정: 해당 경로 예외 승인 또는 Executor 승인/상태 변경 경로 재설계. 이 경로의 구조 기준 채택은 보류한다. 동적 호출(ops.approve, ex.approve)은 이름 일치로 추정한 값이라 정적 확정이 아니며, 도구가 낸 재귀 표시(save→save, approve→approve)는 같은 이름의 서로 다른 함수를 잘못 연결한 것으로 직접 확인했다. 실제 재귀는 stable뿐이었고 제거했다.
