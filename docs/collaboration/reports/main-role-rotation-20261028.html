구현된 사용자 흐름

  1. 메인 패널에서 새 메인 실행하며 교대(또는 한도 소진 시 한도 소진으로 교대(복구))를 누른다.
  2. 이전 메인의 새 배정·승인·통합·리뷰 시작이 정지된다(교대 중). 진행 중인 구현 에이전트는 중단하지 않는다.
  3. 도구 상태와 실제 Git 헤드로 체크포인트(.state/main-checkpoints/)를 저장한다. 마지막 인계문이 없어도 만들 수 있다.
  4. 새 메인 프로세스(codex exec --sandbox read-only / claude --print --permission-mode plan)를 입력 묶음 폴더에서 실행한다. 구독 로그인·과금 가드와 한도 차단을 그대로 거친다.
  5. 새 메인이 체크포인트 해시·세션 토큰·관찰한 Git 헤드를 돌려주면 도구가 실제 Git과 다시 대조하고, 모두 일치할 때만 메인과 세대(generation)가 바뀐다.
  6. 승인 장부 범위 안의 행동(승인·통합·배정)만 기존 기능으로 수행한다. 수행 근거가 있으면 교대 완료, 행동이 없으면 인수됨(완료 아님)으로 표시한다.

권한 승계와 중복 메인 방지

  • 승인 장부: 근거·허용 행동·저장소·브랜치·대상 작업·조건으로 기록. 에이전트 이름이 아니라 장부가 기준이라 메인이 바뀌어도 그대로 승계된다. 도구는 승인을 만들지 않고 기록·조회·검사만 한다.
  • 승계 안 됨: force push·이력 재작성·승인 범위 확대(어떤 장부 항목이 있어도 거부), 특정 세션에 묶인 승인, 철회된 승인. 실험 행동은 장부에 그 실험이 있어야 하고, 이 도구는 실험을 직접 실행하지 않는다.
  • 중복 메인 방지: 교대 중 정지, 세대(generation)·세션 ID·세션 토큰 해시, 행동 ID 장부. 인수 확인이 끝나기 전에는 이전 메인만, 후에는 새 메인만 상태를 바꾼다.
  • 실행기가 ./develop으로 에이전트를 감싼 경우 에이전트에게 중첩 실행을 요구하지 않도록 한 앞선 변경은 그대로다(이번 작업은 건드리지 않음).

미검증·남은 제약

  • 실제 CLI에서 미확인: 설치된 codex/claude 버전의 세션 재개·도구·권한 동작, 실제 한도 오류 문구 전체, 한도 잔량 정보 제공 여부. 잔량·사전 자동 교대는 추정하지 않아 구현하지 않았다.
  • 실제 새 메인이 출력 규약(마지막 줄 JSON)을 지킬지는 첫 실제 실행에서 확인해야 한다. 지키지 못하면 "결과 JSON을 읽지 못함"으로 인수하지 않고 실패를 기록한다.
  • 새 메인 프로세스는 읽기 전용이라 파일을 직접 고치지 않고, 행동은 도구가 기존 기능으로 수행한다. push는 이 도구의 새 메인 행동에 연결하지 않았다(범위 밖).
  • 서버가 재시작되면 진행 중이던 새 메인 실행은 결과 불명으로 처리하고 같은 요청을 다시 보내지 않는다.
  • 교대 중에는 이전 메인의 화면·API 상태 변경을 정지한다. 도구는 누가 클릭하는지 모르므로 사용자 본인의 직접 조작까지 막는 보안 장치는 아니다.
  • 이 브랜치의 AGENTS.md·PAIR_CODING.md는 main의 최신본보다 오래됐을 수 있다. 통합 시 충돌은 현재 메인이 확인한다.
