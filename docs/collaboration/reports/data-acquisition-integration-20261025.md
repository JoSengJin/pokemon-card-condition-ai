## D1 봉인 자료의 비노출 집계 설계 — 미구현·실제 탐색0

**집계 담당자와 개발에 반환하는 정보를 분리한다.** 별도 보관 담당자가 전용 보관 영역에서 수를 센다. 개발 checkout이나 공유 로그에 D1 자료를 두지 않는다. 현재 후보 수는 확인하지 않아 모른다.

1. 개발 측은 이미 개발에 노출된 실물 group·원본/decoded 사진 SHA의 제외 목록과 고정 D1 기준 버전만 보관자에게 전달한다. 보관자가 내부 목록과 대조한다. 사진 해시만으로 다른 각도의 동일 실물을 찾을 수 없으므로 출처·실물 연결이 확인되지 않은 후보는 보류한다.
2. 보관자는 실물별 distinct 수, 질문×앞뒤×양성/정상의 알려진 정답, 권리·앞뒤 대응·사용 이력·촬영 조건을 내부에서 확인한다. 미응답은 정상으로 만들지 않고 사진·패치 수로 실물을 늘리지 않는다. 면/구역 질문을 구분하고, 같은 실물이 여러 구역으로 양쪽 클래스를 지원하더라도 각 클래스 안에서는 한 번만 센다.
3. 상세 건수·부족 셀·예시 사진·정답·개별 SHA·경로·버전별 증감은 **보관 측에만** 저장한다. 개발에는 봉인 접수ID, 기준 버전, 대상 범위, 전체 조건의 준비완료/미완료/미확인만 반환한다. 미완료 원인별 건수도 반환하지 않는다. 이는 수집 준비 상태이며 D2 통과나 정확도를 뜻하지 않는다.
4. 개발 측이 수량·예시를 반복 질의하는 자동 경로는 만들지 않는다. 상태 알림도 필요한 인계 시점으로 제한한다. checkpoint·전처리·threshold·지원범위·보류정책을 고정한 뒤 승인된 한 번의 독립 시험을 요청한다.
5. 독립 시험의 정식 결과 보고에서는 기준이 요구하는 분모·실물 수·사건 수를 공개한다. 이를 준비 중 건수 비공개와 혼동하지 않는다. 시험 결과를 개발에 썼다면 다음 후보에 미사용 독립 시험으로 재사용하지 않는다.

기존 `coverage_report`는 train/val의 A3 20단위/5실물을 집계하므로 D1 30실물 충족을 판정하는 데 사용하지 않는다. 파일럿 A/B의 단위 투영에는 기존 함수 그대로 재사용한다. 이번에는 D1 파일·행·사진·정답 탐색, 집계 구현, 권한 변경을 하지 않았다.
