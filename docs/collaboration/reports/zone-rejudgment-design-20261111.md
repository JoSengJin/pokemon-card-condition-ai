# 구역 라벨 범위 재판정(C) 설계안 — 2026-11-11 (미승인, 실행 전)

개발 진척 78/100 유지. 이 문서는 설계만이며 사람 응답·학습·추론·라벨 변경을 하지 않았다. 근거: `label-scope-sensitivity-20261111.md`(S1에서 FP 167→75, 66그룹).

## 문제 정의
FP 160곳 중 92곳은 사람이 점선(구역 안 후보) 안에서 결함을 확인했다. 이는 같은 구역을 정상으로 저장한 기존 라벨과 사람의 확대 판정이 어긋난다는 뜻이다. 새로 물을 질문이 아니라 **어느 기준을 평가의 기준으로 삼을지의 정책 결정**이 핵심이다. 그러나 S1의 FN 영향은 TN 쪽 숨은 결함에 달려 있고 TN은 45/1239곳만 확인했다. 이것이 유일하게 부족한 근거다.

## 제안 단계
1. (사람 확인, 소규모) TN 구역 무작위 60곳의 최고 반응 패치 후보를 기존 후보 질문("점선 안에 보이는 손상이 있나요?")과 같은 화면·같은 판정(있음/없음/판단 불가)으로 받는다. 이미 판정한 303곳은 제외, 사진 그룹당 1곳, fold별 균등, 시드 고정. 완료 판정은 다시 묻지 않는다.
2. (계산, 학습 없음) TN 숨은 결함율을 Wilson 95% 신뢰구간과 함께 산출하고 S1의 FN'를 외삽 범위로 보고한다.
3. (정책) 사전 규칙: 숨은 결함율 상한(95%)이 20% 이하이면 "후보 확대 기준을 병기 보고하는 이중 보기(현행 라벨 + 확대 기준)"를 사용자에게 제안한다. 상한이 20%를 넘으면 TN 전수 후보 확인 없이는 확대 기준 재채점을 할 수 없다고 보고한다. 결과를 본 뒤 20%를 바꾸지 않는다.

## 하지 않는 것
기존 라벨·게이트(FN≤67/370, FP≤112/1406)·평가 분모·모델·진척 배점 변경, 자동 라벨 수정, unknown 추정, 새 표현 학습. 이중 보기 채택은 별도 사용자 승인 사항이다.

## 필요한 사람 일
폰에서 60곳(10곳씩 6묶음 권장)에 대해 기존과 같은 후보 화면으로 답하기. 승인되면 기존 후보 생성기(`tools/diagnostics/mobile-point-review-20261110/ten.py`)로 묶음을 만든다.
