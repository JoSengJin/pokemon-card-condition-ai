## 2. 입력 경로 지도 (코드에서 읽은 사실)
모서리 모델 점수 한 개가 나오기까지(기존 3개 실험과 오류 14장의 기반 경로):
1. **행**: 구역 `box = region_box(카드 상자, area)`. 카드 상자를 3×3으로 나눈 바깥 칸이다(`card_condition/regions.py:16`, 구역 = 카드 상자의 1/3). 카드 상자는 사람이 확인한 값(`box_reviewed`)이다. 행은 사진 단위 5겹 그룹 교차검증(`tools/experiments/edge-back-grouped-cv-20261031/worker.py:23` `fold_of`, 시드 고정)에 쓰인다. 행 수 946, 실험은 한 그룹을 뺀 942행을 쓴다(`corner-coverage-mask-20261124/worker.py:46`).
2. **자르기**: 사진을 `ImageOps.exif_transpose`로 돌린 뒤 `floor(l·w)`~`ceil(r·w)` 정수 영역으로 자른다(`card_condition/side_experiment.py:41-47` `prepared_image`, `:65` `view_tensors`). 사람이 보는 검토 화면은 같은 구역에 **25% 패딩**을 더한다(`tools/relabel_zone_pages.py:41`, `tools/diagnostics/corner-size-threshold-20261123/measure.py:11`). 모델은 패딩 없는 구역만 본다.
3. **축소**: `ImageOps.pad`로 448×448에 맞추고(비율 유지, 쌍선형, 회색 128 채움; 작은 크롭은 **확대**된다) 정규화한다. 패치 유효 마스크는 따로 `physical_pixel_mask`가 `ImageOps.contain`과 `round` 오프셋으로 만든다(`card_condition/local_wear_cnn.py:50`). 사진 변환은 `pad`, 마스크는 `contain`+`round`로 서로 다른 함수라 1px 어긋날 수 있는지는 코드만으로 확정하지 못했다.
4. **방향**: 기본 경로는 네 모서리를 뒤집지 않고 한 head가 네 방향을 함께 배운다. 뒤집는 변형은 이미 실험했다(`tools/experiments/corner-canonical-orientation-20261124/transform.py`, 잘못 표시 9→12, `corner-canonical-orientation-20261124.md`). 구역 이름(area)은 카드 기준이 아니라 **사진 기준** 3×3 위치다(카드 상자가 축에 정렬된 사각형이기 때문).
5. **저장된 특징·head**: DINOv2 ViT-S/14 패치 토큰 1024×384(`z.shape != (1024, 384)` 검사), 선형 head는 fold별로 저장(`artifacts/experiments/20261121T005441-5720b2eb/fold-heads.pt`)돼 있고 `heads[folds[group]]`로 고른다. 특징은 저장하지 않고 실행마다 다시 계산한다(`grep torch.save` 결과 head 저장 1곳만). 후속 실험은 `plan.input_sha256`으로 입력 해시를 고정하고 대조 재계산 차이가 2e-6 이하여야 한다(`corner-coverage-mask-20261124/worker.py:98-100`). 점수는 구역당 최고 패치 확률, 카드는 구역 최대(`corner-card-ranking`의 `summarize`).

## 4. 판정 기준 (상호 배타, 사진 열기 전 고정)
**구역 단계.** 각 결정 구역·비교 구역마다 항목 1→2→3→4→5(데이터가 흐르는 순서) 순으로 본다.
- 어긋남이 **처음** 나오는 항목 하나에만 그 구역을 배정한다(`첫 어긋남 배정`). 같은 구역이 두 항목에 해당해도 앞 항목으로만 센다.
- 모든 항목이 정상이면 "이상 없음". 어긋남은 없고 하나 이상이 측정 불가면 "측정 불가".
- 측정 불가: 꼭짓점이 홀더·가림·사진 밖이라 보이지 않거나, 구역 크기·틈을 읽을 수 없을 때. 판단 불가를 정상·어긋남으로 채우지 않는다.

**묶음 단계.** 아래 순서로 **먼저 맞는 하나**만 쓴다. 한 구역이 둘 이상에 걸리는 경우도 이 순서가 우선한다.
1. **판단 불가**: 결정 구역 17개 중 "측정 불가"가 **6개 이상**(1/3 이상). 이때는 항목별 결론을 내지 않고 "입력 경로는 판단 불가"로 끝낸다.
2. **원인 확인**: 한 항목 X가 다음 세 조건을 **모두** 만족.
   (a) 결정 구역 중 X로 배정된 구역을 가진 카드가 **3장 이상**(14장 중).
   (b) 비교 구역(34구역)에서 X로 배정된 비율이 25% 이하이면서 결정 구역 비율의 절반 이하. 분모는 측정 가능한 구역만이다.
   (c) X의 어긋남이 점수를 올리거나 내리는 경로를 코드로 설명할 수 있고, **점수 열람 승인 뒤** 그 구역의 최고점 패치 위치가 어긋난 영역과 겹치는 것을 확인(점수·패치 열람 승인이 없으면 (c)는 미충족).
   S5(실행 전체)는 (b)를 "비교 구역도 같은 값"이므로 만족시킬 수 없다. S5는 "원인 확인"이 아니라 "입력 불일치로 결과 무효" 경고로만 쓴다(원인 확인 후보에서 제외, 별도 보고).
3. **불충분**: 위 1·2에 해당하지 않는 모든 경우. 어긋남이 0개이거나, 어긋남이 있어도 (a)(b)(c) 중 하나 이상 미충족. 이 경우 입력 경로가 문제가 아니라고 선언하지 않는다. "이 기준으로 원인을 못 찾음"일 뿐이다.
- 항목별로 세 칸(원인 확인/불충분/판단 불가)에 장수만 쓴다. 14장·17구역이라 비율·유의성 표현을 쓰지 않는다.
- 후보 항목이 둘 이상 (a)~(c)를 통과하면 서로 겹치지 않는 구역 집합이므로(첫 어긋남 배정) 둘 다 보고하되, 모델 변경이나 전처리 변경 근거로는 쓰지 않는다.
