## 핵심 변경

- **무과금 가드** (`nocharge.ts`, `adapters.ts`): 환경변수 이름, Claude 설정(`apiKeyHelper`, `env`의 API 키 이름, `forceLoginMethod`≠`claudeai`, 읽을 수 없는 파일)의 키 이름, 금지 옵션(`--bare`, `--max-budget-usd`, `--betas`), `confirmedSubscriptionAuth`, `--help` 옵션 확인을 시작 전에 검사. 값은 읽거나 기록하지 않고 `auth.json`·키체인은 열지 않는다. 구독 한도 도달은 정지(서비스 유지·실제 실행 거부·사용자 확인으로만 해제), 확실한 과금 문구는 서비스 종료.
- **수동 모드** (`executor.ts`, `workflow.ts`): 도구가 에이전트를 띄우지 않고 소유권 잠금만 유지. "작업 완료"로 기존 Git 검사→작업 테스트→리뷰→승인 흐름, 취소·재시작·결과 다시 수집.
- **누구 차례·시작 프롬프트·메인 인계**: 차례는 상태에서 파생. 시작 프롬프트는 기존 Codex 프롬프트 구조(작업 위치·브랜치·시작 HEAD·읽을 문서·허용 파일·검사·금지·인계 형식)를 규칙으로 조립하고 경로는 복사 시점에만 사용. 인계 문서는 브랜치에 커밋하지 않고 상태 폴더에 저장(PAIR_CODING §4).
- **푸시·되돌림** (`push.ts`): 점검(fetch·fast-forward·커밋별 이력의 금지 경로/5MB/비밀 패턴·통합 후 검사 실패·`--dry-run`) → SHA 앞 12자 입력 → SHA를 지정한 일반 push → `ls-remote` 사후 확인. 되돌림은 `git revert` 커밋을 만들고 푸시 전 트리와 같은지 확인한 뒤 같은 절차로 푸시. 비밀 패턴 오탐은 커밋·파일·줄 단위 사용자 확인.
- **진행률 초안·메인 역할** (`progress.ts`, `mainRole.ts`): 통합 브랜치에 커밋된 `development-progress.json`의 미완료 항목 원문 인용, 제안 파일은 자동 선택하지 않음. 메인 이양은 안전 확인·기록·인계 메모만 하고 권한은 강제하지 않음.

## 남은 결정·리스크

1. **이 브랜치 이력 푸시 시 오탐 확인 8건**: 수정 전에 커밋된 가짜 키 리터럴이 두 커밋에 남아 있다(`cc09adc5` `test/nocharge.test.ts` 5줄, `67d38f37` `test/e2e.test.ts` 3줄). 모두 테스트용 가짜 문자열이다. 이력 재작성은 하지 않았으므로 푸시 점검에서 해당 커밋·파일·줄을 사용자가 "오탐으로 확인"해야 한다(위치는 점검 화면에 표시됨).
2. **메인 이양과 규칙 충돌**: `PAIR_CODING.md`·`AGENTS.md`는 main 통합·푸시를 Codex 담당으로 정했다. 도구의 이양은 표시·기록이며 규칙을 바꾸지 않는다. Claude가 통합·푸시를 맡을지는 사용자가 규칙을 먼저 정해야 한다.
3. **`--bare` 기본값 변경 가능성**: 문서가 `claude -p`의 기본값이 bare가 될 예정이라고 한다. 그러면 구독 로그인이 아니라 API 키를 요구한다. CLI 업데이트 후 어댑터 인자를 재확인해야 한다.
4. **푸시는 취소할 수 없음**: 되돌림은 revert 커밋을 새로 올리는 것이며 이력에는 원래 커밋이 남는다. 이미 올라간 비밀값은 되돌림으로 지워지지 않으므로 점검이 핵심 방어선이다(알려진 모양만 잡음).
5. 허용 파일은 실행 후 diff로만 검사한다(수동 모드에서는 에이전트 세션을 감독하지 않음).
6. 통합 후 검사는 동기 실행(최대 10분)이며 통합 잠금을 잡는다.
