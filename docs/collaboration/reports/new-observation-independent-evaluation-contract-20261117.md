## 3. 새 관찰과 표시 조건

### H: 기존 표면 규약을 사용하는 평가 — 주 평가 지정은 새 제안

- 판정 단위는 사전에 고정한 카드 후면의 표면 구역이다. 구역 ID·box·원사진SHA를 보존하고 구역 전체를 보게 한다. 모델이 만든 후보 상자·점선·heatmap·최고점 위치는 제공하지 않는다.
- 원사진 전체 문맥과 구역 경계를 함께 제공한다. 확대 관찰은 기존 규약의 ‘평소 확대 기준’을 허용한다. 정확한 고정 배율이 과거에 확정돼 있었다고 주장하지 않는다.
- 앞으로의 화면 프로파일에 renderer 버전, viewport CSS 크기, 기기 pixel ratio, 표시 이미지 크기, 원사진/표시 파생본SHA, crop/회전/압축/보간 설정, 확대 기능과 배율/이동 이력을 기록한다. 원사진을 AI로 복원·선명화하거나 합성 세부정보를 추가하지 않는다.
- 응답은 정상/결함/판단 불가/미확인의4상태다. 초기값은 미확인이고 자동 정상·미확인 일괄 정상 처리를 두지 않는 것을 제안한다. 기존 완료 답의 형식이나 값은 변경하지 않는다.
- 반사·흐림·가림·배경/경계 혼입 등 관찰 제한 사유와 자유 메모는 별도 필드에 기록한다. 사유를 손상 정답이나 기존 관찰 제한 모델의 새 정답으로 자동 전환하지 않는다.

### A: 확대 없는 제품 관점의 평가 — 선택적 보조 평가 지정은 새 제안

- 확대 없는 고정 표시 프로파일에서 보이는 표면 자국을 별도로 판정한다. H 라벨을 A에 복사하지 않고, 확대에서만 보인 흔적을 A 양성으로 자동 전환하지 않는다.
- A 프로파일의 정확한 viewport·이미지 표시 크기·리사이즈 설정은 새 수집 전에 승인·고정한다. 과거 ‘확대 없음’만으로 특정 화면 크기나 실제 관찰조건까지 확정됐다고 쓰지 않는다.
- H와 A를 함께 수집한다면 서로 다른 판정자 배정을 우선 제안한다. 같은 사람이 H를 본 뒤 A를 판정한 답은 H의 영향을 받지 않은 독립 A 판정으로 주장하지 않는다. A를 먼저 답한 뒤 봉인해도 두 관찰의 완전한 독립성이 보장되는 것은 아니다.
- 기존 A 카드 집계(양성 구역≥1이면 카드 양성, 양성0이고 판단불가/split≤2이면 카드 정상, 그 외 미확정)는 기존 보조 보고 규칙으로 보존한다. 새 사람 A 자료에 이를 적용할지, 새 판정자 구성을 어떻게 할지는 수집 전 별도 확정한다. 미확정 구역이 포함된 카드 정상이라는 제한도 함께 보고한다.
- A는 선택적 별도 수집 경로이며 필요 인원/비용 승인이 없으면 실행하지 않는다. H/A를 합쳐 하나의 정답이나 성능 수치로 만들지 않는다.

**결론의 범위 제안:** H만 수집/평가하면 결론은 H 기준의 누락·오탐 변화로 제한한다. H 통과를 확대 없는 제품 A 성능 개선이나 제품 전체 성능 개선으로 승격하지 않는다. 제품 A 개선을 주장하려면 별도 승인된 A 관찰·정답·수용 기준으로 같은 새 자료의 baseline/후보를 비교해야 한다. H/A의 수집 범위·주/보조 역할과 각각 허용할 결론은 실행 전에 고정하며, A를 생략한 경우 보고서에 A 개선 미평가를 명시한다. 이는 기존 target이나 과거 A 결과를 변경하는 규칙이 아니다.

‘충분히 봤다’는 선언과 화면 로그는 절차 근거다. 사람의 주의·실제 지각이나 외부 자료 미열람을 완벽히 증명하지는 않는다. 표시/입력 시스템은 아직 구현하지 않았고 실제 기기에서 검증하지 않았다.

- 판정 전 노출 사고·payload 혼입·응답 충돌은 기록하고 해당 응답을 맹검 근거로 사용하지 않는다. 재요청이나 정상 추정으로 자동 복구하지 않는다.
- 노출 사고의 처리 단위도 사전 정의가 필요하다. 어떤 정보가 어느 응답/판정자/session에 도달했는지, 판정 전후 시점을 기록하고 영향이 의심되는 범위를 격리하는 방식을 제안한다. 범위를 특정하지 못하면 관련 session을 보수적으로 격리하고 범위 확정 전 해당 자료의 맹검 적격성을 인정하지 않는다. 응답 한 건만 제외할지 session 전체를 제외할지의 판정 권한·기준은 미정이다. 격리/제외 ID와 원래 모집 분모는 보존하며, 사고 뒤 유리한 행만 골라 남기거나 대체 수집/재요청을 자동 진행하지 않는다.

이 절은 앞으로 충족할 계약이며 현재 프로그램이 강제하거나 이미 비노출이 검증됐다는 뜻이 아니다. 후보521 저장 화면의 `region_target` 사례는 이 분리의 필요성을 보여주는 근거이며 실제 답 오염의 증명은 아니다.

## 5. 새 자료 선정과 개발/평가 분리

1. 아직 완료 판정이 없는 새 실물 그룹을 모집단으로 정의한다. 공개/합법적 취득 경로·사용 권한·보존 범위를 확인한다. 모델이 틀린 사진·점수가 높은 사진만 고르는 수집은 주 독립 평가로 사용하지 않는다.
2. 같은 실물의 앞뒤·재촬영·다른 매물·중복 사진은 같은 그룹이다. 새 파일명이거나 새 촬영이라는 이유만으로 독립 실물로 취급하지 않는다.
3. 응답·모델 점수를 보기 전에 source 모집단, 그룹 제외 규칙, seed, 역할 배정법, 표본 수, 예비분 처리 순서를 고정한다. 새 development pool과 sealed final evaluation pool은 실물 그룹 단위로 분리한다. 역할을 판단 결과에 따라 바꾸지 않는다.
4. 기존 학습/개발/모델선택/평가/갤러리와 같은 실물·사진은 새 독립 최종 평가에서 제외한다. 기존104/303곳은 읽기 전용 진단 근거로만 보존한다. 완료 라벨을 다시 요청하지 않는다.
5. D1 봉인·표면 보충시험·폐기105·예약보류9그룹과 기존 보호 자료는 열거나 재사용하지 않는다. 중복 배제를 위해서는 권한 있는 보관자가 라벨/사진을 노출하지 않는 승인된 제외 목록 또는 검토 결과를 제공해야 한다. 이 접근 권한이 확보되지 않으면 중복 배제를 완료했다고 주장하지 않고 모집/실행을 차단한다.
6. 향후 허용된 중복 확인은 실물 계보, 원파일SHA, 디코딩 이미지 중복을 구분해 기록한다. 해시가 달라도 같은 실물일 수 있다. 검출 도구와 보관자 확인의 한계를 기록한다. 이번에는 이 검사를 실행하지 않는다.
7. 개발 자료만으로 모델/특징/학습법/임계/집계·화면을 선택한다. 후보 코드·가중치·전처리·임계·baseline·평가 정답·지표 계획을 봉인한 뒤에만 최종 평가를 한 번 연다.
8. 최종 평가를 보고 수정·선택한 순간 그 평가자료는 이후 독립 시험이 아니라 소비된 개발/회귀 자료다. 실패 뒤 같은 자료로 튜닝하고 ‘새 독립 통과’라 하지 않는다.

평가 대상량을 바꾸지 않도록, 실물당 사진 수·사용할 면/사진의 선정법·구역 포함 규칙과 동일 가중할 단위를 수집 전에 정해야 한다. 예를 들어 한 실물의 재촬영 사진이 많다는 이유로 그 실물이 전체 오탐률에 더 큰 가중치를 갖는 설계를 의도 없이 만들지 않는다. 구역 단순 합산, 사진 균등, 실물 균등 중 어느 모집단의 오류율을 추정할지는 미정이다. 가중 추정을 선택하면 아래 §7의 분모/차이 식도 그 정의에 맞춰 사전 고정하고 단순 건수와 구분해 보고한다. 현재 단순 구역 식이 실물 균등 추정치인 것처럼 해석하지 않는다.

표본 수는 이번에 임의로 확정하지 않는다. 사전 개발/별도 계획 자료에서 예상 오류율·짝 불일치율·그룹 상관·미확정률과 사람이 감당할 수집 비용을 근거로 최소 양성/정상 실물 수와 총 그룹 수를 정해야 한다. 최소 검출 개선폭과 검정력도 함께 정한다. 최종 평가 점수/결과를 보고 표본을 늘리거나 종료점을 고르지 않는다. 클래스 수·유효 관찰 수가 사전 최소치에 못 미치면 `insufficient_data`로 평가를 열지 않는다. 보충 규칙도 결과 열람 전에 고정한다.

추가로 최소 유효 판정 실물 수, 미확정/불일치 비율의 허용 범위와 분모, 필수 관찰 로그·표시 프로파일 누락의 적격성 처리, 처리 실패/모델 거부의 수용 처리를 고정해야 한다. 수치·규칙은 아직 미정이다. 둘 모두 답한 쉬운 일부만 남겨 개선돼도 전체 모집단 개선으로 주장하지 않는다. 동일한 사전 적격성 규칙을 두 모델에 적용하고 원 모집 집합·유효 집합·제외 집합을 함께 보존한다. 조건 미달 시 보류하며 결과를 본 뒤 허용 범위를 완화하지 않는다.

## 6. 자료 산출물 계약 — 경로/형식 제안, 아직 생성하지 않음

향후 승인되면 원사진·원응답·실물 식별자는 Git 제외 신규 수집 루트에만 보존한다. 기존 artifacts와 manifest는 덮어쓰지 않는다. 아래는 요구 역할이며 현재 프로그램/파일이 있다는 뜻은 아니다.

- custody manifest: 실물/사진/구역의 익명 ID와 원본 계보, 출처/권한, 원파일·표시 파생본 해시, 중복 배제 근거, 역할 배정·seed, 변경 이력.
- access/release ledger: 역할별 단계·허용 파일, 개발자에게 전달한 집계 범위, 겸직 제한, 후보/계획 동결 시점, 최종 평가 자료 공개·열람 이력. 아직 형식·접근 제어 구현은 없다.
- rater packet: 익명 ID, 표시 이미지와 사람용 구역 경계, 지시문·display profile. 모델/기존 정답 정보는 포함하지 않는다.
- observation receipt: 원문 응답,4상태, 실제 기록된 시각/관찰 조작, 판정자·session·화면 버전, 판단 불가 사유, 노출 사고. 정확 위치를 직접 받지 않았으면 위치 정답은 null이다.
- truth seal: 최초 답·불일치·조정/미확정·제외 사유·고정 분모와 정답 버전. 원응답은 불변이며 모델 오류를 이유로 정답을 변경하지 않는다.
- evaluation release: 봉인된 baseline/candidate/checkpoint/전처리/지표 계획/수용 기준과 자료 버전. baseline 예측을 후보 예측으로 복사하지 않는다.

## 7. 누락·오탐 개선 판정 — 기존 기준과 새 제안을 분리

### 기존 고정 평가

기존1776구역의 FN57/370·FP167/1406은 과거 개발 baseline 기록이다. 기존 FN≤67/370·FP≤112/1406·AUC+0.03 등의 게이트는 그대로 보존한다. 새 자료의 baseline 점수·분모를 대신하지 않는다. 게이트 통과만으로 ‘두 오류 동시 감소’를 주장하지 않는다.

### 새 독립 평가의 제안 기준(승인 전)

- H 주 평가는 동일한 새 사진·구역·정답·전처리·임계0.5에서 동결 baseline과 후보를 짝 비교한다. 사람 정답의 미확정/제외 집합은 두 모델에 동일하게 적용하고 전체 모집 수·제외 수·이유도 함께 공개한다. 모델이 어렵다고 거부한 행을 분모에서 삭제하지 않는다.
- 단순 구역 합산을 선택할 경우 `ΔFNR = FN_candidate/N_positive - FN_baseline/N_positive`, `ΔFPR = FP_candidate/N_negative - FP_baseline/N_negative`로 정의한다. 가중 방식은 아직 선택하지 않았으므로 이 식을 최종 추정량으로 확정한 것은 아니다. 건수·분모·비율·%p와 해결 오류/새 오류 ID를 모두 기록한다.
- **누락·오탐 동시 개선 지지:** 두 차이의 점추정이 모두 음수이고, 실물 그룹을 함께 재표집하는 짝 bootstrap의 각95% 구간 상한이 모두0 미만일 때만 지지하도록 제안한다. 재표집 횟수·seed·정의와 최소 검출 개선폭/표본 수는 실행 전에 승인·동결한다. 한 구역/사진을 독립 표본처럼 재표집하지 않는다.
- 두 점추정이 감소해도 구간이0을 포함하면 ‘이번 평가의 점추정 감소, 독립 개선 판정 보류’다. FN 유지/FP 감소는 ‘누락 유지·오탐 개선’이고 동시 개선이 아니다. 어느 한쪽이라도 악화하면 동시 개선으로 채택하지 않는다.
- **검출 가능성과 실용적 수용 기준을 구분한다.** 최소 검출 개선폭(MDE)은 표본 수/검정력을 설계하는 입력이다. §8.2에서 누락·오탐 각각의 최소 실용 개선폭을 별도 수용 조건으로 설계하기로 사용자 선택을 완료했다. FNR/FPR 각각의 구체 개선폭 수치와 점추정/구간에 적용할 수용식은 미정이며 결과 전에 승인·동결한다. 작은 차이의 통계적 방향성 지지를 실사용 효용 입증으로 바꾸지 않는다. 정책 선택이나 MDE 설정을 구체 개선폭·통계 수치·절차 또는 실행의 승인으로 확대하지 않는다.
- bootstrap의 방식·추정량/가중치 적용·짝/그룹 보존·반복 횟수·seed·구간 산출법과, 양성/정상 분모가0인 재표집·퇴화 구간·구간 산출 불가의 처리 규칙은 미정이다. 유리한 재표집만 남기거나 seed/방식을 바꿔 통과시키지 않는다. 규칙이 없거나 유효 구간을 만들지 못하면 개선 통과를 선언하지 않는다. 본문의95%·상한<0도 여전히 승인 전 제안이다.
- AUC 차이와95% 그룹 구간은 별도 보고한다. AUC가 좋아도 FNR/FPR 동시 개선을 대체하지 않는다. 기존+0.03 기준을 새 분모에 자동 이식하거나 완화하지 않는다. 새 독립 평가의 AUC 추가 합격폭이 필요하면 결과 전에 별도 승인한다.
- A 보조 평가를 수집/승인했다면 새 사람 A 정답으로 baseline/candidate를 같은 자료에서 비교하며 카드 임계0.8·0.5를 병기한다. H와 별도 표/분모로 보고하고 여러 임계 중 유리한 것만 골라 성공으로 쓰지 않는다. 순위 예산20%·30%도 별도 보고이며 오류 게이트의 대체가 아니다.
- 미확정·불일치·판단 불가·처리 실패·모델 거부 수와 유효 판정 비율을 공개한다. 데이터/그룹/정답/점수 무결성 실패, 표본 부족, 노출 사고는 절차 실패/판정 보류이며 모델 성능0이나 가설 반증이 아니다.
- 공개만으로 적격성을 충족하지 않는다. §5에서 고정할 유효 실물 수·미확정률·관찰 로그 등 최소 조건과 실패/거부 처리 규칙을 먼저 적용한다. 해당 규칙이 미정인 현재는 평가 진입 불가다. 특정 유효 관찰 범위에서만 성립한 결과를 제외된 어려운 사진/실물이나 전체 제품 성능에 일반화하지 않는다.
- 한 번의 독립 평가가 위 조건을 충족해도 운영 채택·Gemini fallback 변경·실사용 시간 절감까지 자동 입증하지 않는다. 기존 회귀 보호·채택 승인·실사용 검증은 별도다.

새 두 오류 개선 기준의 수치 제안(95%·상한<0)은 과거 사용자 승인값이나 이미 통과한 기준이 아니다. 이 계약 검토 뒤 실제 실행 기준으로 사용할 때 승인·사전 고정이 필요하다. 기존 게이트는 변경하지 않는다.

## 8. 실행 전에 반드시 채울 항목과 종료 조건

아래가 모두 구체적으로 고정되기 전 상태는 `not_executable_pending_collection_contract_approval`다.

§8의 항목은 **A. 기존 근거로 유지·정리할 조건 / B. 사용자 정책 결정 / C. 결정 후 자료에 따른 산정·기술 설계**로 구분한다. 같은 항목에도 세 단계가 섞일 수 있다. 예를 들어 ‘실물 단위 분리’는 유지할 조건이지만, 목표 모집단은 사용자 결정이고, 필요한 실물 수는 그 결정 뒤의 산정 대상이다. 2026-11-17 사용자는 B의 정책 방향7개를 모두 권장안으로 선택했다. 기준 기기·사진 출처·인력·시간·금액 한도는 명시적으로 미정이며, C의 수치·표본 수와 새 실행 권한은 확정하지 않았다.

### 8.4 결정·산정의 순서와 실행 차단

순서는 **A의 기존 조건 유지 → B의 정책 방향 선택(이번 반영) → 기준 기기·사진 출처·인력·시간·금액 한도 등 남은 구체 결정 → C의 표본/통계/표시/접근 절차 산정·설계 → 값·정본·적용 시점·승인 상태 고정**이다. 선정/응답 전에 고정해야 하는 항목을 뒤늦게 채우거나 최종 평가 점수를 이용해 사전 조건을 결정하지 않는다. B를 선택했다고 C가 자동 확정되는 것도 아니고 C를 기록했다고 수집/평가가 승인되는 것도 아니다.

B/C의 미정 항목이 남아 있거나 필요한 권한·비노출/분리 수단이 준비되지 않았으면 `not_executable_pending_collection_contract_approval`을 유지한다. 수집 승인은 학습·추론·모델 비교·외부AI·운영 변경 승인으로 자동 승계되지 않는다. 이번에는 정책 방향7개 선택만 반영했다. 기준 기기·사진 출처·인력·시간·금액 한도 및 표본 수를 포함한 미정 수치를 확정하지 않았고, 라벨 재요청·실제 수집·검증 실행·학습·추론·main 통합·push는 승인하거나 실행하지 않았다.

이 항목을 고정하는 것은 새 원인 증명이나 자료 수집 완료가 아니다. 현재 승인된 기준을 다시 질문하지 않으며 새 절차의 미정 항목만 대상으로 한다. 표본 수·관찰조건의 임의 숫자를 만들어 계약을 실행 가능하다고 꾸미지 않는다.

향후 모델 비교 실행은 별도 승인 후 고유 가설ID·단일 변경 변수·수정 전 snapshot·동일 baseline·사전 수치 기준을 등록하고 `./experiment --plan ... -- ...` 공통 경로를 따라야 한다. 실행기가 새 자료/짝 비교 지표를 지원하는지는 아직 확인하지 않았고, 이 문서는 지원 구현이나 우회 실행을 승인하지 않는다. 실제 성능 평가를 하면 사진/구역별 사람 정답·모델 출력·FN/FP 분모·%p HTML과 record.json 실제 상태/판정을 함께 보고해야 한다.

## 9. 이번 산출물·리스크·롤백

이번 산출물은 이 수집 계약 문서와 기존 [task](../tasks/stable-low-reference-cause-design-20261116.md)·[감사 보고서](stable-low-reference-cause-design-20261116.md)의 연결/반영 기록이다. §8에는 사용자가 선택한 정책 방향7개를 기록했다. 기준 기기·사진 출처·인력·시간·금액 한도 및 표본 수 등 미정 수치는 확정하지 않았다. 구체 절차·통계 수치는 미정 또는 승인 전 제안이며 `not_executable_pending_collection_contract_approval`을 유지한다. 최초 원인 대조 설계의 `not_executable_missing_evidence`도 해제하지 않는다.

검토된 별도 초안의 정책 선택·미정 조건·실행 차단을 보존하고 저장소 상대 링크와 문서 반영 이력만 조정했다. 이번 확인은 문서 diff·허용 경로·링크·공백과 로컬 커밋 상태 확인에 한정하며 모델/설계 검증 실행이 아니다. 소스 함수 수·호출 경로 변경은 없다. HTML은 설계 문서 준비 범위로 생성·열기·렌더하지 않는다. 라벨 재요청·실제 수집·검증 실행·학습·추론·외부 호출·main 통합·push는 하지 않는다.

주요 리스크는 H/A 의미 혼합, 후보/크롭 답의 구역 전파, 모델 기반 표적선정, 비노출 payload의 정보 누출, 사람 판정 불일치, 실물 중복, 평가자료 소비, 표본 부족과 사후 기준 변경이다. 정책 선택이나 문서 보존이 사람 정답·맹검·독립성·성능 개선을 입증하지 않는다.

원본 기록·.claude/·D-LOC·보호 자료·다른 worktree는 보존한다. 이번 문서 반영만 철회하려면 해당 로컬 커밋을 revert하고, 소유권 확대까지 철회하려면 그 선행 커밋을 이어서 역순 revert한다. 최종 SHA는 task와 마찬가지로 자기 참조를 피하기 위해 커밋 인계 응답으로 전달한다. 실제 롤백은 하지 않는다.
