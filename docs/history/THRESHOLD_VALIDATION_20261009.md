# 임계값 진단 — 2026-10-09

## 질문과 결과
MobileNet 고정 특징 기준 모델의 누락을 임계값 변경만으로 줄일 수 있는지 확인했다. 기존 val 18면의 예측을 재사용했으며 학습·test 평가·운영 설정 변경은 없다.

| 항목 | 실제 양성/음성/미확인 | 양성 누락 0일 때 최소 오탐 | 음성 오탐 0일 때 양성 누락 |
|---|---|---|---|
| 평가 가능 | 13 / 5 / 0 | 평가 불가 4/5를 평가 가능으로 오판 | 평가 가능 12/13 누락 |
| 센터링 결함 | 7 / 8 / 3 | 8/8 | 5/7 |
| 모서리 결함 | 3 / 11 / 4 | 11/11 | 3/3 |
| 엣지 결함 | 6 / 8 / 4 | 7/8 | 4/6 |
| 표면 결함 | 2 / 10 / 6 | 5/10 | 2/2 |

따라서 이 기준 모델은 임계값만 바꿔 누락과 오탐을 동시에 해결할 수 없다. 양성·음성 출력의 순서가 겹친다. 일부 엣지는 임계값을 낮추면 오탐 없이 2건 검출할 수 있지만 여전히 4건 누락되므로 운영 통과 근거가 아니다. 미확인은 정상으로 계산하지 않았다.

## 구현과 근거
- 기존 routing-audit에 per_label_threshold_analysis 추가. 새로운 CLI·의존성 없이 표준 Python 사용.
- 실제 양성·음성의 출력 경계와 0/.5/1, 최대 출력 바로 위에서 혼동행렬 및 precision/recall 계산. 같은 출력값의 양성·음성을 임의로 갈라 평가하지 않는다.
- val 정답으로 찾은 후보이며 자동 채택하지 않는다. 단일 클래스만 있으면 후보는 null이다.
- 보고서: artifacts/threshold-audit-20261009.json. 입력: artifacts/visibility-complete-20261009.jsonl, artifacts/glare-location-audit-20261009.json.
- 전체 28개 테스트 통과. 동점 출력, 미확인 제외, 단일 클래스, 기존 매물 단위 후보 및 Gemini 절감0 검증.

PR/임계값 분석 도입 조건은 도래했으나 현재 규모에는 scikit-learn이 필요하지 않다. 반사 위치 및 결함 영역의 사람 라벨을 확보해 모델이 구별할 수 있는 입력을 보강하는 것이 다음 순서다. 현재 데이터만으로 timm/OpenCV 도입 효과를 가정하지 않는다.
