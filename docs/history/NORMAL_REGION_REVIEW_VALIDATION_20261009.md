# 정상 구역 보강 안내 개선

## 원인과 다음 단계
현재 train 구역 정답은 모서리 정상1/결함12, 엣지 정상1/결함20, 표면 정상1/결함40이다. 미확인은45/37/17개로 유지한다. 기존 자동 이동은 결함 위치 지정만 다뤄 정상 구역 보강을 안내하지 않았다. 원인 전체를 자료 불균형만으로 단정하지 않으며 더 많은 정상 자료로 검증해야 한다.

## 변경 파일 / 핵심 diff
- card_condition/review.html: 정상 구역 보강 시작/다음 후보 버튼. train의 기존 면별 결함 없음(0)인데 같은 항목의 명시적 구역0이 없는 면을 안내한다. 제외·val·test·앞뒤 사진 누락은 건너뛴다. 사용자가 모드를 시작했을 때만 저장 후 정상 후보로 이동한다. 기존 결함 위치 안내는 그대로 유지한다.
- tests/review_validation.test.cjs: 순서·현재 후보 시작·순환·val/test/제외 건너뛰기·null 보존·JSON 재로딩 뒤 완료 판정 검사.
- REGION_HUMAN_REVIEW_20261009.md, master CONDITION_ANALYSIS_TODO.md: 보강 절차와 다음 개발 조건 기록.

## 검증
Node 검토 회귀검사 통과, Python 구역 테스트7개 통과. 실제8766 페이지에서 미저장 입력 없음(저장 버튼 비활성) 확인 후 새로고침해 새 버튼을 적용했다. 버튼을 눌러 a 앞면 모서리 안내·사진·구역 입력이 표시된 것을 확인했다. 실제 사람 라벨은 수정/저장하지 않았다. 실제 save→다음 후보 동작의 브라우저 저장 검사는 이 변경에서 수행하지 않았으며 후보 선택 로직은 자동 테스트로 검증했다. 서버 재시작 없음.

## 사람 확인 / 실험
우선 기존 train 그룹 a·b·c·h·p 앞면에서 관찰한 정상 구역을 보강한다. 하나라도 명시적0을 저장하면 그 면/항목은 안내 대상에서 빠지지만, 데이터가 충분하다는 의미는 아니다. 가림·반사는 null 유지하며 실제 손상이 보이면 사람 판단대로 기록한다. 이후 새 snapshot→동일 조건 학습→정상 오탐/결함 누락을 함께 비교한다. 이전 개발 자료를 test로 옮기지 않는다.

## 리스크 / 롤백
후보는 면별 라벨 기준이라 실제 정상 여부를 보증하지 않는다. 수동으로 넘긴 항목은 라벨 변경이 없으므로 나중에 다시 후보로 나타날 수 있다. 정상 라벨을 저장한 항목의 완료 판단은 영속 JSONL 기준이다. 안내 모드만 페이지 새로고침 때 해제된다. 미저장 입력이 있으면 시작/넘기기 버튼은 비활성이다. 모델 가중치·점수·Gemini 호출 경로는 바꾸지 않았다. 현 서버 HTML만 적용했으며 wheel은 이번 UI 수정으로 재빌드하지 않았다.
롤백은 새 normal-review 버튼·normalReview 상태·nextNormalRegionTask 및 정상 분기만 제거하면 된다. JSONL/기존 모델은 수정하지 않는다.
