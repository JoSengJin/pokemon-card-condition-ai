# eBay 자동 학습 사진 확보 (2026-10-14, 0.4.89)

## 결과

기존 eBay API 연결로 새 후보 12매물의 사진 **73장**을 수집했다. 매물 상세의 `image`와 `additionalImages` 전체를 읽으며 첫째/둘째 사진을 앞뒤로 간주하지 않는다. 기존 learn의 매물 ID·디코딩 이미지와 일치하는 자료는 새 후보에서 제외했다.

Gemini의 매물별 사진 판독 12회에서 카드 한 장인 온전한 앞면과 로고·전체 카드가 보이는 뒷면 후보 7쌍을 골랐다. 선택된 뒷면 7장을 별도의 묶음 호출 **1회**로 다시 검사해, 투명 받침대가 하단 테두리를 가린 2쌍을 보류했다. 최종 **5매물·10장**만 원본 그대로 learn의 `ebay-pair-…/front·back` 폴더로 내보냈다. 다른 7매물은 수집 원본에만 남겼다. 실제 자동 선택에는 앞면1/뒷면6, 앞면1/뒷면10도 있었으며 이 두 매물은 추가 검증에서 받침대 가림으로 보류됐다.

자료 확보에 실제 Gemini **13회**를 사용했고, 동일 결과 재실행은 캐시를 재사용해 **0회**였다. 기존 소비 앱의 `setting`, `ai_usage`, `ai_usage_bucket` 한도를 같은 SQLite 트랜잭션으로 검사·예약한다. 스키마 변경이나 매물·장부 DB 등록은 하지 않는다. 기본 실행 한도는 실제 API 시도 14회이며, 모델 fallback 시도도 이 한도에 포함된다. 모델의 상태 분석 성능과 실제 Gemini 상태 분석 호출 절감은 이번 작업에서 측정하지 않았다.

## 선별 계약

- 매물별 전체 사진을 한 번에 보고 앞면/뒷면/기타/불확실, 카드 수, 전체 카드, 로고 여부를 기록한다. 단일 카드 매물이 아니거나 조건을 충족하는 앞뒤가 없으면 보류한다.
- 앞면과 뒷면은 서로 다른 사진이어야 하고 각각 카드 한 장이 온전히 보여야 한다. 뒷면에는 Pokémon 또는 구형 일본판 POCKET MONSTERS 로고가 보여야 한다.
- 두 번째 뒷면 검사에서 상·하·좌·우 **전체 바깥 테두리**, 모든 모서리, 로고가 보이고 가림이 없음을 각각 확인해야 자동 내보내기를 허용한다. 받침대가 투명해도 테두리에 겹치면 보류한다.
- 그림자·반사·마모 자체를 결함 또는 부적합으로 자동 확정하지 않는다. 요구한 카드 경계·로고를 확인하지 못할 때만 사진 적합성을 보류한다.
- `.9` 기준은 비전 모델이 보고한 확신도 필터이며, 실제 보정 확률이나 정확도 보장이 아니다. 두 단계가 같은 모델이므로 독립적인 정확도 검증도 아니다. 자동 판독은 잘못 통과시킬 수 있다.
- 출력은 train **후보**다. 모든 상태 라벨은 null, 사람 검토자는 공란, `pair_verified=false`다. eBay의 NM/played 문구·모델 선별을 정상/손상 정답으로 만들지 않는다. 카드 영역·동일 실물·정상/결함은 기존 라벨 화면에서 사람이 확인한 뒤 학습한다.

## 실행과 재개

독립 프로젝트 루트에서 실행한다. 소비 프로젝트는 API 인증과 호출 한도 장부만 재사용한다.

```sh
.venv/bin/python tools/collect_ebay_dataset.py \
  --consumer-root "$POKECOLLECTOR_ROOT" \
  --learn "$POKECOLLECTOR_ROOT/learn" \
  --quota-db "$POKECOLLECTOR_QUOTA_DB" \
  --output artifacts/ebay-auto-intake-20261014 --limit 12 --screen-limit 14
```

같은 output으로 재실행하면 완료한 수집·판독과 뒷면 검증을 재사용한다. 사진 해시가 달라지면 캐시 사용을 거부한다. 새로운 수집은 새 output 폴더를 지정한다. `--query`를 여러 번 주어 검색 문구를 지정할 수 있다. 기본 NM/played/old back 검색은 교대로 후보를 가져오며 제목은 라벨이 아니다. quota/서비스 오류는 실패 기록을 남기고 판독을 멈춘다. 실패·미검증 사진은 자동 내보내지 않는다.

`artifacts/ebay-auto-intake-20261014/summary.json`이 현재 내보낸 manifest를 가리킨다. `index.html`은 전체 사진과 선택·보류 근거를 보여준다. 사람 라벨 작업은 export를 복사한 `labels-review.jsonl`에서 수행해 재실행이 사람 라벨을 덮어쓰지 않게 한다.

## 변경·검증·롤백

- 변경: `card_condition/ebay_dataset.py`, `tools/collect_ebay_dataset.py`, `tests/test_ebay_dataset.py`, `pyproject.toml`, `README.md`, 이 문서. 소비 프로젝트는 TODO 기록·새 learn 사진 폴더·호출 한도 장부만 갱신한다.
- 검증: 전체 추가사진 수집/중복URL 제거/원본 보존/완료 재개, 순서와 다른 앞뒤 선택, 다중 카드·잘림·로고 누락·불확실 보류, 잘못된 인덱스·NaN 거부, 앞면 확대사진 제외, 받침대 가림 제외, 추가 검증 없는 자동 export 차단, 상태 정답 null/동일 실물 미확인 유지, 기존 export 덮어쓰기 거부, 이미지 변경 거부, 기존 호출 한도 준수.
- 실제 eBay 수집과 Gemini 판독·묶음 재검증을 실행했고 판독 캐시 재실행에서 추가 API 호출 0회를 확인했다. 이는 상태 분석 AI의 정확도 향상 증거가 아니다.
- 리스크: 사진만으로 동일 실물임을 확정할 수 없고, 리스팅이 달라도 다른 촬영의 같은 카드일 수 있다. 디코딩 픽셀 중복 검사는 이를 모두 잡지 못하므로 신규 독립 시험으로 자동 배정하지 않는다. 자동 선별도 오판 가능하므로 상태 라벨 단계의 사람 검토를 유지한다.
- 롤백: 새 도구·모듈·테스트·문서 변경을 되돌리고 이번 `artifacts/ebay-auto-intake-20261014`와 해당 `learn/ebay-pair-…` 신규 폴더만 제거한다. 기존 라벨·모델은 변경하지 않았다. 실제 사용한 Gemini 호출 한도 기록은 삭제하지 않는다. 보완 전 미라벨 사본은 `.backups/ebay-intake-*`에 보존했다.
