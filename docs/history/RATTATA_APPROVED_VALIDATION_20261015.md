# AI 초안 → 사람 승인 → 학습 비교의 첫 실제 실행

## 사람 확인과 정답 보존

사용자는 꼬렛 앞면8·뒷면6 정상 엣지 후보를 모두 직접 확인했다고 대화로 답했다. 이 명시적 답변을 근거로 기존 승인 함수를 실행해14건의 승인 출처·fingerprint·검토자를 저장했다. UI 클릭 승인 기록이 없던 상태를 정상으로 추정한 것이 아니다. AI 초안을 사용자 확인 없이 정답으로 바꾸지 않았다.

저장된 사람 모서리2점·엣지1점과 모든 좌표·종류를 보존했다. 정상 승인은 엣지 종류·확인된 구역에만 한정하며, 미확인 표면·그라데이션·동일 실물은 추정하지 않았다. 앞뒤는 같은 train 그룹으로 보수적으로 묶었고 `pair_verified=false`를 유지했다.

## 고정 비교 결과

- 새16구역 patch 중 엣지 정답은 정상14·손상1이다. 모서리2점은 겹치는 patch에 별도 종류로 보존했다.
- 기존 기준과 동일한 frozen MobileNet, tiles224,20epochs,balance,balanced-selection,seed42로 실행했다. 새 그룹/ID/디코딩 이미지 중복 없음·기존val50patch 완전 일치·test 미사용을 준비 스크립트가 검증했다.
- 같은 모델선택용 엣지27구역(결함15·정상12): 기준 TP15/TN7/FP5/FN0 → 후보 TP13/TN6/FP6/FN2.
- 누락0→13.33%(+13.33%p), 정상 오탐41.67→50.00%(+8.33%p). 사전 누락0 유지·오탐5 미만 기준에 실패해 후보 미채택, 기준 모델 그대로 유지했다.
- 이는 승인 워크플로가 실제 학습에 연결됐다는 증거이지 성능 향상 증거가 아니다. 한 카드의14개 구역을14개 독립 실물로 세지 않는다. 악화한 후보를 운영에 넣거나 사람 정답을 바꾸지 않는다.
- 개발 단계4/6 약67%, 이번 운영 정확도 변화 없음·후보는 악화·독립 일반화 개선 미확인·운영 Gemini 상태 분석 절감0건.

`artifacts/rattata-approved-20261015/index.html`에 같은 평가 사진의 전후 구역·점수·사람 정답·누락/오탐 및 모든27구역 표를 표시한다. 입력·report hash와 confusion counts를 재계산해 검산했다. `artifacts/rattata-ai-draft-20261015/index.html`은 승인14건·미승인0건·원래 사람 결함3점을 별도로 보여준다.

## 다음 AI 보조 자료

기존 한도 안에서 새3매물10사진을 확보했다. 단일카드 판독3회+뒷면경계v3 묶음1회, API4회. 여러 카드 묶음 매물은 보류하고 꼬부기·피카츄2쌍만 내보냈다. NM/LP 제목은 정답으로 쓰지 않았다.

Codex가 네 원본 사진을 직접 보고 영역과 정상 엣지 후보26개를 sidecar에 작성했다. 꼬부기 앞면7·뒷면8, 피카츄 앞면6·뒷면5다. 애매한 모서리·케이스/하단 구역 등은 제안하지 않았다. 아직 네 영역은 사람 확인 전이며 후보는 승인할 수 없는 대기 상태다. 새 작업 파일의 모든 상태 정답은null, 별도 관찰 제한도 추정해 정답화하지 않았다. localhost:8789 실제HTTP200 확인. 사용자가 두 카드의 AI 초안을 확인 후 저장하겠다고 답해 휴먼인루프 단계에서 기다린다. 꼬렛 및 이전 완료 카드는 재요청하지 않는다.

## 변경·검증·리스크·롤백

- 주 기능 파일: `label_drafts.py`, `review.py`, `review.html`, `test_label_drafts.py`, 버전0.4.93·README. 계약 상세는 `AI_DRAFT_REVIEW_VALIDATION_20261015.md` 참고.
- 추가로 승인 버튼의 선택 누락·검토자 누락은 기존 빨간 필드 오류·포커스/스크롤 함수를 사용하도록 보완했다. 조용히 승인 안 된 것으로 느끼지 않도록 문제 항목에 안내한다.
- 기존40회귀·최종 초안9테스트 통과. 실제 화면 함수를 Node DOM 대역으로 실행해 기본 미선택, 차단항목 제외, 선택 누락 오류, 미저장 편집 보호, 명시적 승인 요청을 검증했다. 실제 사용자 대신 테스트로 정상 후보를 승인하지 않았다.
- wheel0.4.93 빌드 성공, 최종 새모듈·승인API·HTML 파일 bytes와 wheel 내용 일치 확인. 실제 브라우저 클릭 렌더 QA는 하지 않았다.
- 신규 artifacts: `rattata-approved-20261015`, `rattata-ai-draft-20261015`, `ebay-teacher-candidates-20261015`; 사용자 작업/초안 파일과 소비 TODO 및 문서 갱신. 기존 기준 모델은 보존했다.
- 리스크: AI 제안도 틀릴 수 있으며 사람의 일괄 승인이 품질을 보장하지 않는다. 후보의 악화가 라벨 오류를 증명하는 것도 아니다. 새26개 후보는 아직 정답이 아니며 독립 평가 자료도 아니다.
- 롤백: 신규 학습 후보는 사용하지 않으면 된다. AI 초안 UI는 sidecar를 보관해 수동 입력으로 복귀할 수 있다. 이미 확인한 사람 정상14구역과 결함점은 임의로 삭제하지 않는다. 필요하면 JSONL 저장 전 `.bak`과 승인 provenance를 보존한 뒤 복원한다. 호출 장부는 삭제하지 않는다.
