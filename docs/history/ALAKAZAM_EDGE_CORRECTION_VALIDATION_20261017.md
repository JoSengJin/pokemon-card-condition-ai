# 후딘 엣지 정정과 클릭 종류 기본값 제거

사용자 정답 ‘두 점 모두 바깥 엣지 손상’에 따라 앞면2점의 label만 surface_defect→edge_defect로 변경했다. xy좌표·front box·하단중앙 표면정상0·기존 뒷면 모든 annotation은 그대로 보존했다. 앞면 전체 표면은 null로 되돌렸으며 정상0으로 확장하지 않았다. 실제8794 API에서 엣지2점·전체표면미확인·하단중앙표면정상0 확인. 기존 사용자 확인에 의한 정정이며 모델 예측으로 라벨을 바꾼 것이 아니다.

## 실제 원인과 방지
review.html의 pointKind가 미선택시 단일 양성 종류를 추론하거나 surface_defect를 기본값으로 줬다. 이번 입력이 실제로 기본값 때문에 발생했는지는 단정할 수 없으나, 종류 미선택으로 잘못된 정답을 만들 수 있는 경로다. 새 사진은 종류를 명시적으로 고르도록 빈 기본값을 넣고, 선택 전 클릭은 상태 안내+select focus만 수행하며 점/라벨/commit을 만들지 않는다. 동일 사진에서 사용자가 선택한 종류는 rerender 뒤에도 유지한다. 기존 라벨을 자동 정정하지 않는다.

## 남은 사람 의존과 리스크
뒷면17점은 현재 표면으로 저장되고 좌표가 테두리 근처에 있어 종류 확인이 필요하다. 뒷면영역도 아직 미확인이므로 이번 학습에는 포함하지 않았다. 앞면과 같은 종류일 것으로 추정해 고치지 않는다. 정상확인 완료범위는 다시 묻지 않는다.
UI는 새 사진마다 종류를 한 번 선택해야 하는 동작 변화다. 회귀값은 탐색 결과이며 운영 개선 아님.
롤백: out/review.before.html과 review_validation.before.cjs를 원래UI/테스트로 복원하면 이번 코드 변경을 되돌릴 수 있다. 모델 후보는 운영 미적용. 사람이 정정한 라벨은 연구실패를 이유로 되돌리지 않는다. out/labels-before-correction.jsonl은 감사용으로 보관하고 최신 라벨을 덮어쓰지 않는다.
