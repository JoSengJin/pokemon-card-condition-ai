# 표면 모델 비판적 재점검 — 2026-10-16

## 결론

사진 부족만을 이유로 반복 학습·추가 라벨을 요청한 접근은 충분하지 않았다. 앞뒤를 하나의 표면 분류기로 처리하는 도메인 혼합을 분리하자, 동일한 고정 특징과 기존 정답만으로 두 개발 평가에서 누락·오탐이 함께 감소했다. 이것은 연구 후보 개선이며 운영/독립 시험 성능이 아니다.

## 사실과 추론의 분리

- 최근 MobileNet 세 초기값 모두 20단계 중 **1단계**가 검증 BCE 최선이었다. 학습 loss는 .679→.516 / .696→.524 / .697→.523으로 감소하지만 검증 loss는 .673→.718 / .702→.765 / .727→.736으로 악화했다. 반복 횟수 증가가 해결책이라는 근거가 없다. 초기값 의존성과 분포 부적합이 관찰된다.
- 기존 train 143구역/30실물을 하나씩 완전히 제외해 학습했다. 뒷면 영상 특징은 TP34/TN8/FP5/FN8인데, 픽셀 없는 앞뒤·구역 위치만으로 TP34/TN9/FP4/FN8이었다. 위치별 정답 구성에 기대는 위험 신호다. 예측이 동일하거나 픽셀이 전혀 무용하다는 인과 증명은 아니다.
- 사람의 작은 결함점은 `point_dataset.py`에서 3×3 구역 양성으로 변환되고, `patch_features`에서 해당 구역을 224px 입력/전역 특징으로 만든다. 기스·오염·벗겨짐이 같은 surface 목표다. 위치와 질감 혼동/미세 손상 희석은 여전히 가능하지만 이번 시험으로 그 원인까지 확정하지 않는다.
- 학습/검증 실물·디코딩 이미지 중복 차단과 미확인 제외 경로를 확인했다. 이번 감사에서 잘못된 정답 자동 생성이나 직접적인 val 학습 편입은 발견하지 않았다. 모든 과거 데이터 이력 전체를 감사한 것은 아니다.
- 같은 4실물/38표면 구역 val을 반복 사용해 모델 선택한 결과는 독립 일반화 증명이 아니다. 기존 BCE 선택과 보고용 비가중 FN/FP가 다른 목적이라는 점도 개선 판단을 어렵게 했다.

## 수정한 실험 방식과 한 가지 알고리즘 변경

`artifacts/surface-critical-audit-20261016/run.py`: train만 읽고 매번 한 실물의 앞뒤 모든 구역을 제외. fold마다 가중치/클래스 균형을 다시 계산. 고정 ImageNet MobileNet, 수렴 logistic L2=1, 임계값.5. 제외 실물과 학습 실물/이미지 해시 교집합0 assert. 데이터 및 파라미터 탐색 없이 `앞뒤 공통 head → 앞뒤별 head`만 비교한다. 앞뒤 분리에 따라 각 head의 실물 가중치도 해당 면 자료 안에서 계산한다.

| 실물 제외 교차검증 (143구역) | 누락/결함93 | 오탐/정상50 | 정확도 |
|---|---:|---:|---:|
| 공통 head |31/93 (33.33%)|21/50 (42%)|63.64%|
| 앞뒤 head |20/93 (21.51%)|19/50 (38%)|72.73%|

누락 -11.83%p, 오탐 -4%p, 정확도 +9.09%p. 앞면 FN23→13/51 FP16→15/37, 뒷면 FN8→7/42 FP5→4/13. 실물별 총 오류 7개 개선/20개 동일/3개 악화(a, ㄴ, 마그마). 모든 카드의 개선은 아니다. 동일 학습 집합에서 가설을 만든 탐색 교차검증이며 완전한 nested 평가가 아니다.

`check_validation.py`: 위 설정 고정 후 기존 val에서 확인. train만 fit하며 val은 score에만 사용. 기존 난수 초기화 AdamW와의 개선 비교가 아니라 같은 수렴 logistic 공통/분리의 대조다.

| 기존 개발 val (38구역) | 누락/결함19 | 오탐/정상19 | 정확도 |
|---|---:|---:|---:|
| 공통 head |5/19 (26.32%)|8/19 (42.11%)|65.79%|
| 앞뒤 head |0/19 (0%)|6/19 (31.58%)|84.21%|

누락 -26.32%p, 오탐 -10.53%p, 정확도 +18.42%p. 새 실물 독립 시험이 아니므로 서비스 정확도 84.21%라고 주장하지 않는다. 앞뒤 head를 각각 기존 RegionAnalyzer 체크포인트로 내보냈고 실제 API 38구역과 대조했다. 점수 최대차 1.1921e-7, TP19/TN13/FP6/FN0 일치. 호출자가 front/back에 맞는 모델을 명시적으로 골라야 하며, 일반 API가 면을 자동 판별하는 기능은 없다.

## 다음 개발 기준

사진 한 장씩 추가→같은 val 재학습을 기본 루프로 쓰지 않는다. train 실물별 제외 진단 → 한 가설의 고정 비교 → 실물별 부작용 확인 → 후보 동결 → 독립 시험 순서를 따른다. 새 입력 없이는 독립 성능을 주장하지 않되, 그것을 모든 개발 중단 이유로 사용하지 않는다. 앞뒤 분리 연구 head의 API 형식 내보내기와 정확한 side 선택 시 출력 일치는 검증했다. 서비스에 연결하기 전에는 side 선택 강제 계약과 잘못된 side 전달 방지를 추가 검증해야 한다. 운영 교체는 별도 근거가 필요하다. OpenCV는 재도입하지 않았다.
