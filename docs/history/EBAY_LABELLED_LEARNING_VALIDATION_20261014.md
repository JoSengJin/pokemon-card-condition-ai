## 사람 정답과 입력 고정

- 자동 선별한5매물10사진에 사용자가 저장한 결함점을 유지했다. 뮤츠·고우스트 뒷면 영역 확인은 사용자 답변/추가 저장을 근거로 완료 처리했다. 검토자 공란에는 사용자의 ‘라벨 저장 완료’ 출처를 기록했으며 임의로 J라는 이름을 추정하지 않았다.
- 사용자가 망나뇽 앞뒤 바깥 테두리 전체가 정상이라고 확인해 엣지16구역만0으로 반영했다. 센터링 쏠림과 다른 결함 미확인은 보존했다. 정상16구역은 **한 실물**에서 나온 것이며16개의 독립 카드가 아니다.
- 실제 학습 패치는 새34구역이며 엣지 정상16·손상11구역이다. 새 엣지 손상11구역은 모두 뒷면, 새 정상 구역의 실물 그룹은1개다. 면 전체의 결함1만 있고 위치 근거가 없는 항목은 국소 엣지 패치로 추정해 만들지 않았다.
- 야도란 앞면 점은 사용자가 ‘모서리만 손상, 엣지 미확인’이라고 정정해 live 라벨에 반영했다. 정정 전후 `point_rows` 결과가 완전히 같음을 확인했다. 해당 면의 엣지 위치점이 없었기 때문에 실험 입력은 바뀌지 않았으며 같은 재학습을 반복하지 않았다.
- `artifacts/ebay-labelled-train-20261014/prepare.py`가 입력 해시·중복 디코딩 이미지·group 분리·10면 영역 확인·새 정상/손상 동시 존재를 검사하고 snapshot을 만들었다. 기존 val50행 전체가 전후 동일하다. test 사진은 읽거나 학습에 편입하지 않았다.

## 한 번에 바꾼 가설

1. 기존 기준의 train에 새5매물만 추가했다. `tiles`, 224px, 20epoch, seed42, 클래스/실물 균형 및 검증 선택 방식은 같았다. 결과는 `artifacts/ebay-labelled-train-20261014/`에 있다.
2. 같은 보강 manifest에서 `--side-balance`만 켰다. 기존 학습 손실 비중은 앞면정상18.79%·앞면손상12.78%·뒷면정상31.21%·뒷면손상37.22%였다. 새 옵션은 네 셀을25%씩 배분하고 각 셀 내부에서 실물 그룹을 동등하게 가중한다. val의 분포로 train 가중치를 계산하지 않는다. 결과 악화로 **이 비중 편향만 해결하면 된다는 가설은 지지되지 않았다.** `artifacts/ebay-side-balance-20261014/`에 있다.
3. 같은 보강 manifest와 기존 가중치에서 입력 해상도만224→448로 바꿨다. 결과 악화로 해상도 증가를 해법으로 채택하지 않았다. `artifacts/ebay-resolution-20261014/`에 있다.

새 외부 라이브러리는 추가하지 않았다. 기존 PyTorch 학습·타일 입력으로 실험했다. OpenCV는 사용자 순서대로 보류 중이다. 백본을 바꿔야 한다고 단정할 근거도 이번 시험만으로는 없다.

## 다음 자료 확보와 실제 중단 조건

사용자에게 새 사진을 다시 요청하지 않고, 개발한 수집기로 damaged/heavily played/near mint 제목을 교대로 검색해 새6매물33사진을 수집했다. 제목은 상태 정답으로 사용하지 않는다. 6회의1차 판독으로4쌍이 후보가 됐으나, 공유하는 Gemini 일일 판독 한도에 걸려 **마지막 뒷면 묶음 검증이 대기** 중이다. 이4쌍은 아직 learn으로 내보내지 않았고 모델 학습에도 사용하지 않았다. 입력·판독 결과를 저장했으므로 한도 초기화 후 같은 output으로 재개하면 완료한1차 판독을 다시 호출하지 않는다. 새 학습 자료의 실제 앞면 손상·정상 범위는 이후 사람이 확인해야 한다.

재개 출력 폴더: `artifacts/ebay-front-candidates-20261014`. 이 폴더에 대해 `--limit 6 --screen-limit 7 --query 'pokemon card damaged' --query 'pokemon card heavily played' --query 'pokemon card near mint'`를 사용한다. quota 대기 상태를 해소해도 이 스크립트가 자동 예약 실행되는 것은 아니다.
