# 0.4.94 · 라벨 화면 단순화

## 결과

기본 흐름을 **검토자 → 카드 영역 확인 → 센터링 → 사진 클릭 또는 AI 확인 → 저장**으로 줄였다. 검토자 입력은 하나로 통합했다. 정상/결함/관찰 제한의 기존 데이터 의미는 바꾸지 않았다.

- 중복 사진 갤러리는 ‘등록 사진·원본 보기’로 접고, 같은 사진을 본문에 반복 노출하지 않는다.
- 내부그룹ID·앞뒤 사진 지정·동일 실물 확인·전체 카드 라벨·분할·제외는 ‘카드·데이터 관리’로 이동했다. 라벨/누수 방지에 필요한 관리 기능이므로 데이터나 기능을 삭제하지 않았다.
- 키보드 좌표 입력·지점별 종류 수정/삭제·영역 초기화·반복 설명·상세27칸 구역폼은 필요한 때만 펼친다. 키보드 접근과 수정 기능은 유지한다.
- 전체 카드 학습 준비 검사·수동 정상 묶음·JSONL 내보내기도 접힌 관리 메뉴에 배치했다. 부분 결함 학습과 무관한 `Human gradable label is required` 메시지가 기본 화면에 뜨지 않게 했다.
- 기본 하단에는 라벨 저장과 결과 안내만 남겼다. 긴 내부id 대신 카드번호를 표시하고 id는 툴팁/관리 입력에 유지한다.
- 일반 저장 뒤 face-positive만으로27칸 폼을 자동으로 펼쳐 재확인을 유도하던 동작을 제거했다. 일반 저장은 상단으로 이동하고, 명시적인 구역 링크/geometry 검토/수동 정상 묶음일 때만 기존 큐를 이어간다.
- AI 제안 문구의 ‘엣지 결함 · 정상 후보’를 ‘바깥 테두리 · 정상 후보’로 바꾸고 버튼도 ‘선택한 항목이 맞아요/틀려요 · 저장’으로 줄였다. 정상 후보는 사람 확인 전 정답이 아니다.

## 저장 상태와 휴먼인루프

현재 작업 파일에서 꼬부기 앞면 모서리2점·뒷면 모서리1점과 앞뒤 영역 확인이 저장된 것을 확인했다. 피카츄의 영역 확인과 AI 정상 후보 승인 기록은 비어 있다. 사용자가 확인 범위 질문을 이해하기 어렵다고 답했으므로 정상으로 추정해 채우지 않고 미확인으로 유지한다. 화면 단순화 작업에 추가 라벨 입력을 요구하지 않는다. 저장된 결함·센터링·정상/미확인·출처·사진·모델은 이 변경에서 수정하지 않았다.

개발 단계4/6 약67%, 이번 모델 학습·추론 없음·정확도 변화 없음·독립 개선 미확인·운영 Gemini 절감0건. `artifacts/simple-review-20261015/index.html`은 화면 변경 요약이며 직전 실제 모델 성능 비교에 연결한다.

## 검증

- `test_review`, `test_label_drafts`, `test_point_dataset`:25건 통과.
- 실제 저장 핸들러를 Node 대역에서 실행: 일반 저장이27칸 큐를 호출하지 않고 상단으로 이동, geometry/명시적 수동 큐 보존, 저장상태 갱신 확인. 승인 화면 함수도 실제 실행해 공통 검토자·미선택/차단/미저장 보호·승인 요청 검증. 최종 JS 구문 통과.
- HTML 구조 검사: 고유id 중복 없음·관리 항목이 접힌 메뉴 안에 있음·공통 검토자 노출·1열 레이아웃 확인. 직접 클릭·AI 승인에 쓰이는 DOM id와 데이터 연결은 유지했다.
- 실제 in-app 브라우저의 새로고침 후 접근성 트리에서 기본/관리 구성이 의도대로 렌더된 것을 확인했다. 임시 사본의 저장 클릭 E2E와 스크린샷 캡처는 이후 탭 세션 연결 오류로 완료하지 못했다. 이를 실제 저장 E2E 통과로 보고하지 않는다. 코드 실행·Python 저장/승인 API 테스트로 검증 범위를 구분했다.
- 임시 작업 사본과 실제 사용자 JSONL bytes 일치로 라벨 불변 확인. 테스트로 실제 사용자 후보를 승인하거나 라벨을 수정하지 않았다.
- wheel0.4.94 외부 다운로드 없이 빌드하고 최종 review.html 포함을 확인한다.
