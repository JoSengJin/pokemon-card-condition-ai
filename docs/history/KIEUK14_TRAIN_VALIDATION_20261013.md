# ㅋ/14 하단 엣지 화이트닝 학습 보강 (2026-10-13)

사용자가 `learn/ㅋ/14/img.png`와 `img_1.png`를 서로 다른 실물 뒷면으로 확인했다. 사람이 카드 영역과 결함점을 저장했고, 첫 사진은 **좌측 하단**, 둘째 사진은 **하단 중앙** 엣지 결함으로 3×3 구역에 들어간다. 두 면에서 확인하지 않은 구역은 정상으로 채우지 않았다. `data/kieuk14-train-review-20261013.jsonl`의 두 실물은 `train`이며 기존 manifest·고정 체크포인트 및 ㅋ/13 `test`의 그룹·디코딩 이미지 해시와 겹치지 않는다.

`artifacts/kieuk14-train-20261013/inputs.json`은 기존 학습·검증 입력, 새 라벨, 고정 시험 입력의 SHA256을 기록한다. 기존 train 44실물에 새 train 2실물만 더했고 val 14실물은 그대로다. 비교 도구가 val 구역의 라벨·이미지 해시·카드 영역이 동일함을 검증했다. ㅋ/13 test는 두 후보의 개발 이력에 들어가지 않았으며, 이전 시험 결과를 후보 선택에 재사용하지 않았다.

기존 224px과 새 224px은 학습 실물 두 장만 달리한 비교다. 새 224px의 누락률은 **-6.7%p**, 오탐률은 **-8.3%p**다. 같은 새 입력을 쓴 448px은 224px보다 누락과 오탐이 모두 늘어 이 해상도 변경은 채택하지 않는다. 이는 이미 모델 선택에 사용한 val 결과이며 새 실물에 대한 정확도 향상 증거가 아니다. 후보 체크포인트는 연구용으로만 보존한다. 운영 모델·Gemini fallback·임계값은 바꾸지 않았고 실제 Gemini 호출 절감은 0건이다. 개발 기반은 4/6(약 67%) 그대로다.

`point-audit`가 전체 카드의 `gradable` 값이 없는 유효한 부분 결함 라벨을 거부해, train/val 감사 읽기에서만 `require_gradable=False`를 지정했다. 감사 결과 새 결함점은 두 곳 모두 면별 엣지 결함 1과 일치하고, 구역별 라벨은 미확인이다. `point_rows(..., grid=True)`는 사람 점을 각각 양성 패치 한 개로 변환하며 정상 패치는 생성하지 않는다.

변경 파일: `data/kieuk14-train-review-20261013.jsonl`, `artifacts/kieuk14-train-20261013/`의 등록·합성 입력·후보·비교·감사 자료, `card_condition/point_audit.py`, `tests/test_point_audit.py`, 이 문서, 소비 프로젝트의 `CONDITION_ANALYSIS_TODO.md`. 검증은 사람 영역·점 좌표, 라벨 스키마, train/val/test 실물·해시 분리, 고정 val 동일성, 224/448 비교 보고서 재계산, 부분 라벨 감사 테스트로 수행했다. 전체 Python **168개 테스트 통과**. 첫 샌드박스 실행에서는 로컬 포트 바인딩을 쓰는 테스트 2개가 권한 오류였고, 같은 테스트를 로컬 포트 권한으로 재실행해 모두 통과했다. `point-audit`는 새 두 점을 각각 `lower_left`·`lower_center`로 기록하고 사람 구역 라벨과의 충돌 0건을 보고했다.
