# 0.4.93 · AI 초안과 사람 묶음 승인

초기 구현 이후 사용자가 꼬렛 정상14구역을 대화로 직접 확인해 실제 승인·학습 비교까지 실행했다. 후속 결과·새 자료 대기는 `RATTATA_APPROVED_VALIDATION_20261015.md`를 따른다. 아래 승인0개는 최초 구현 검증 시점 기록이다.

## 목표와 현재 결과

사용자가 카드마다 정상 구역까지 처음부터 클릭하는 부담을 줄인다. Codex가 사진을 보고 구역·종류·정상/결함 후보와 근거를 초안으로 작성하고, 사람은 사진과 비교해 맞는 항목만 선택·승인하거나 거절한다. AI가 더 정확하다는 가정이나 자신감을 정답으로 사용하지 않는다.

꼬렛 원본 앞뒤를 검토해 앞면8구역·뒷면6구역의 **정상 엣지 후보**를 만들었다. 뒷면 좌하단과 우측 중간은 기존 사람이 표시한 결함과 관련되어 제안에서 제외했다. 정상 표면이나 카드 전체 정상은 제안하지 않았다. 기존 사람 모서리·엣지 결함2점과 센터링·면 라벨·카드 영역은 그대로다. 모든 후보는 아직 사람 승인 전이며 학습 정답이 아니다.

최대14구역을 면별 두 묶음으로 선택·승인하는 UI를 제공한다. 실제 사람 소요시간 절감률은 측정하지 않았다. AI 제안 자체의 정확성도 검증되지 않았다. 개발 단계4/6 약67%, 이번 모델 학습·추론 없음, 정확도 변화 없음·독립 일반화 미확인·운영 Gemini 상태 분석 절감0건.

## 데이터와 승인 계약

- 작업 JSONL과 별도로 `labels-review.drafts.json`에 초안을 보존한다. 학습 데이터 생성기는 이 파일을 읽지 않는다.
- 초안은 카드ID·면·원본 파일SHA256·확인한 카드 영역·3×3 구역·결함 종류·제안값·근거·작성자에 묶인다. 초안 내용 fingerprint도 기록한다.
- 화면은 보라색 사각형/`AI?`로 제안을 표시한다. 기본 선택은 모두 꺼져 있다. 기존 빨간 사람 결함점과 구분한다. 실제 카드 상태 모델의 위치 예측으로 표현하지 않는다.
- 사람은 충분히 확인한 항목을 선택하고 검토자를 입력해 승인한다. `POST /api/draft-review`는 기존 loopback Host/Origin/token 및 파일revision 검사를 재사용한다. 클라이언트가 보내는 초안 내용이나 임의 학습 라벨은 신뢰하지 않고 서버의 초안을 사용한다.
- 기존 미저장 편집이 있으면 먼저 저장하도록 한다. 승인 동작으로 이전 편집을 유실시키지 않는다.
- 승인된 구역만 기존 `region_labels`에 들어간다. 결함 승인일 때만 면·전체 결함1도 반영한다. 정상 구역 승인을 전체 카드 정상으로 확대하지 않는다.
- 거절은 검토 기록만 남기며 기존 라벨을 바꾸지 않는다. 선택하지 않은 것은 미확인이다. 이미 검토한 초안은 다시 요청하지 않는다.
- 사진/영역 변경·영역 미확인·기존 구역 정답·정상 후보와 겹치는 같은 종류의 사람 결함점·해당 관찰 제한은 승인 차단 대상이다. 학습용 train만 허용하며 val/test 제안은 승인할 수 없다. 기존 면/전체 정상과 모순되는 결함 후보도 덮어쓰지 않는다.
- `ai_draft_reviews`는 승인/거절·검토자·작성자·fingerprint·실제 제안 내용을 보존한다. 일반 라벨 저장이 이 기록을 지우거나 위조하지 못하며, JSONL export에도 함께 보존한다.

## 실제 검증

- 새 검토 화면 localhost:8788 및 `/api/review` 확인: HTTP200, 초안14개 available, 기존 사람 결함2점, 승인 기록0개. 테스트가 실제 사용자 초안을 승인한 적은 없다.
- `test_label_drafts`, `test_review`, `test_point_dataset`, `test_ebay_dataset`:40건 통과. 마지막 사람 전체 정상 충돌 방어 후 `test_label_drafts`9건 재실행 통과.
- 추가9건은 미승인 초안의 학습 비유입, 일부 정상만 생성, 승인/거절·새로고침·일반 저장·export provenance, 사진/박스/분할/체크 변경, 기존 정답/점/반사 충돌, 중복대상·가짜id·빈검토자·stale revision, 결함 승인, 실제 token보호 HTTP POST를 검증한다.
- 실제 `renderDrafts` 함수를 Node DOM 대역에서 실행해 기본 미선택·차단항목 제외·미저장 편집 보호·선택ID/검토자/승인 요청·응답 후 재렌더를 검증했다. 전체 inline JavaScript 구문 검사 통과. 실제 브라우저 클릭 렌더 QA는 하지 않았다.
- 외부 다운로드 없이 wheel0.4.93 빌드 성공. 새 Python 모듈과 review.html 포함 여부를 확인한다.
- `artifacts/rattata-ai-draft-20261015/index.html`: AI 제안과 사람 표시를 원본 위에 구분해 보여주고, 직전 실제 모델 성능 HTML에 연결한다. 새 추론 결과처럼 표현하지 않는다.

## 변경 파일·영향·리스크·롤백

- `card_condition/label_drafts.py`: 초안 검증·현재 상태 판정·명시적 승인/거절 적용.
- `card_condition/review.py`: snapshot의 초안 제공, 보호된 승인 API, 검토기록 영속 저장·export. 초안 없는 기존 작업 파일은 기존 방식으로 동작한다.
- `card_condition/review.html`: 후보 영역 표시·면별 묶음 선택·승인·거절. 직접 클릭 입력은 유지한다.
- `tests/test_label_drafts.py`, `pyproject.toml`, `README.md`, 본 문서, 소비 프로젝트 TODO. 별도 초안 파일과 시각/검증 artifacts 생성. 기존 사진·모델·사용자 결함점은 변경하지 않았다.
- 리스크: Codex의 정상 제안도 미세 손상을 놓칠 수 있다. 사용자가 확인하지 않고 일괄 승인하면 잘못된 정답이 만들어질 수 있으므로 충분히 본 구역만 승인한다. 구역이 coarse3×3이며 정확한 결함 위치나 심각도 모델은 아니다. 사진/영역이 바뀐 제안은 새로 작성해야 한다.
- 롤백: 초안 sidecar를 별도 보관하면 제안 UI가 나타나지 않는다. 코드/버전 변경을 되돌려 기존 수동 입력으로 복귀 가능하다. 이미 승인한 사람 정답을 자동 삭제하지 않으며, 복원이 필요하면 작업 JSONL의 저장 전 `.bak`과 승인 기록을 먼저 보존한다. 기존 모델은 변경되지 않아 모델 롤백은 필요 없다.
