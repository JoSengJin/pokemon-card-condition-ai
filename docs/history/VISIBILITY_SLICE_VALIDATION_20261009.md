## 결정과 다음 단계

반사 1면으로 별도 반사 탐지 head나 부분 미세조정을 시작하지 않는다. 사람은 남은 평가 불가 면의 사유와 가려진 결함의 `null` 라벨을 확인한다. 새로운 train 실물에서 반사와 비반사 평가 불가 사례를 추가한 뒤 같은 분할 원칙으로 다시 실험한다. `gradable=0`은 사진 관찰의 한계이며 카드 상태 불량이나 구매 제외 정답이 아니다. 현재 모델은 계속 실험용이고 `requires_gemini=true`, 실제 호출 절감 0건이다.

`2026-10-09` 후속 점검에서 기존 선택지에 없던 `perspective`(비스듬한 촬영·원근 왜곡)를 면별 사유에 추가했다. 개발 분할에서 사유 미입력은 `l/front`, `l/back`, `m/back`, `o/back`, `ebay-7db839f540a696/front` 5면이다. 기존 회귀용 `g/front`도 미입력이지만 개발 지표에는 포함하지 않는다. 자유 입력 메모는 자동 정답으로 전환하지 않았고 원본 라벨·분할·모델은 변경하지 않았다. 라벨 서버는 새 검증 코드로 재시작했고 `/api/review` 응답 200을 확인했다.

추가 라벨 저장 후 `artifacts/visibility-complete-20261009.jsonl`을 생성하면서 이전 분할을 보존했다. 개발용 학습·검증 이미지/박스/정답은 이전 snapshot과 같고, 관찰 제한 사유 6면만 추가됐다. 새 `reslice-visibility` 명령은 체크포인트의 이미지 픽셀 해시 및 입력 동일성을 확인한 뒤 기존 검증 예측을 `artifacts/visibility-resliced-20261009.json`에 다시 집계했다. 반사는 train 4면/val 4면, 원근 왜곡은 train 2면/val 0면이다. 반사 val 중 평가 불가 3면을 모델이 모두 평가 가능으로 오판했고 전체 val 오판 수와 가중치는 이전 실험 그대로다. 새 실험으로 성능이 나아졌다고 주장할 근거는 없다.

추가 라벨 감사에서는 사유 미입력은 남지 않았지만 `l/front`, `l/back`, `m/back`의 평가 불가 면에 결함 `0`이 기록되어 있어, 해당 위치가 실제로 보이는지 사람이 한 번 더 확인할 필요가 있다. 보이지 않는 부위라면 `null`이 맞고, 선명하게 보여 결함이 없다면 `0`을 유지한다. 이 감사 항목은 오류 확정이 아니다. 감사 결과는 `artifacts/visibility-label-audit-20261009`에 저장했다.
