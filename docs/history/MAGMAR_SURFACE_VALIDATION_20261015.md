# 마그마 표면 학습 비교와 새 사진 경계 검증

## 성과와 판단

사용자가 저장한 마그마 표면 결함은 앞면23점·뒷면13점(구겨짐3점 포함)이다. 사용자 답변에 따라 두 면의 `box_reviewed=true`와 검토 기록만 반영했다. 앞뒤 동일 실물은 모른다는 답변을 보존해 `pair_verified=false`다. 두 사진을 같은 train 그룹에 묶어 분할 간 누수를 방지하며 동일 실물이라고 주장하지 않는다. 미확인 엣지·정상 구역·반사 위치는 추정하지 않았다.

표면 결함 보강이므로 엣지 전용 타일 모델의 학습에 넣지 않았다. 기존 학습 자료와 마그마를 추가한 자료에 같은 전체 구역 입력·224px·MobileNet frozen backbone·20epochs·class/group balance·balanced selection·seed42를 사용한 대조군/후보를 각각 만들었다. 사전 기준은 표면 누락 증가 없이 표면 오탐 감소다.

동일 모델선택용 val 표면38구역(결함19·정상19): 보강 전후 모두 TP9/TN17/FP2/FN10. 누락52.63%·오탐10.53%, 변화 각각0.0%p. 기준 미달로 후보 미채택·운영 모델 유지. 기존 엣지 타일 모델의 누락0/15·오탐5/12와 다른 타깃/모델이므로 성능 하락 비교로 사용하지 않는다. 개발 단계4/6 약67%, 이번 정확도 개선 없음·일반화 개선 미확인·운영 Gemini 절감0건.

마그마36점은 같은 구역의 중복을 합쳐 표면14구역이 된다. 36개 독립 실물이 아니다. 정상 표면은 추가되지 않았다. 기록상 20회차에는 전후 각각 누락8/19→6/19지만 오탐12/19로 증가한다. 합산 선택과 표면만의 균형 BCE 모두1회차를 선택했으므로 다른 결함의 선택 기준이 표면 개선을 가렸다는 증거는 없다. 마지막 회차를 사후 채택하거나 같은 자료로 반복 재학습하지 않는다.

## 시각화와 검증

- `artifacts/magmar-surface-20261015/index.html`: 사람 결함점36개와 같은 val 사진의 전후 표면 구역·점수·누락/오탐 색 표시, 1회/20회 진단표. 정확한 모델 결함 좌표 예측으로 표현하지 않는다.
- `make_review.py`는 모델 report와 manifest SHA, val 정답·좌표·그룹·이미지 해시 일치, 출력으로 재계산한 confusion counts, HTML 셀/사람점 수를 검산한다. 브라우저 탭 열기는 요청했으며 실제 화면 렌더 검증은 하지 않았다.
- 새 그룹/id/디코딩 픽셀과 기존 train/val 중복 없음. 기존 val 전체 구역 완전 일치, test 읽지 않음. `plan.json`에 두 manifest 해시와 사전 기준, `result.json`에 결과·report 해시를 보존했다.
- `PYTHONPATH=.:tests python -m unittest test_ebay_dataset test_point_dataset test_region_experiment -q`: 25건 통과. 첫 실행은 tests fixture 경로 누락으로 import 실패했고 경로를 맞춰 정상 실행했다.

## 사진 선별 실제 보완

기존 한도 정책 안에서 남은 세 뒷면을 묶음 검증했다. v2가 확대 삽입된 Recall 사진을 통과시켜 v3에 `collage_or_inset` 필수 boolean과 명시적 거부 조건을 추가했다. v3 결과: 캐이시 통과, Recall 합성/가림으로 제외, 에인션트 뮤는 로고 부재/받침대 가림으로 제외. 이번 두 묶음 검증에 API2회 사용했다. 마그마의 사람 경계 확인은 그대로 재사용했다. 사진 선별의 보완이며 카드 상태 AI 정확도 향상은 아니다.

v2에서 잠시 내보낸 미라벨 Recall 사본은 학습에 쓰지 않았으며 `artifacts/ebay-front-candidates-20261014/quarantine`에 옮겨 learn에서 제외했다. 최신 selected manifest는 마그마·캐이시2쌍만 포함한다. 오래된 selected manifest는 과거 중간 결과이므로 최신 `summary.json`을 사용한다. 완료된 마그마 작업 파일은 보존하고 새 캐이시는 `abra-review.jsonl` 및 localhost:8786에서만 확인하도록 분리했다. 서버 HTTP200 확인. 동일 실물/상태 정답은 여전히 사람 확인 전이다.

## 변경·리스크·롤백

- `card_condition/ebay_dataset.py`: 두 번째 경계 검사에도 합성/확대 삽입 거부, 계약v3.
- `tools/collect_ebay_dataset.py`: v3 계약과 사진 SHA가 모두 일치할 때만 자동 경계 캐시 재사용. 해결된 `back_verification` 과거 오류만 삭제하며 다른 단계 오류는 유지.
- `tests/test_ebay_dataset.py`: 합성 거부, 과거 계약 미재사용, 부분 사람 확인·제외·재개·완료 오류 해제·작업 라벨 파일 보존을 실제 CLI main으로 검증.
- `pyproject.toml`, `README.md`, 본 문서, 소비 프로젝트 TODO 및 새 artifacts. 원본/운영 모델 변경 없음.
- 리스크: v3의 실제 세 사진 판독은 일반적인 선별 정확도 보장이 아니다. 구형 자동 경계 캐시는 새 계약에서 재검증이 필요해 추가 호출 또는 대기가 생길 수 있다. 부분 사람 확인은 사진 해시 일치 시 유지된다. 새 표면 검증도 반복 val이므로 독립 정확도 향상을 주장할 수 없다.
- 롤백: 신규 연구 후보를 사용하지 않으면 기존 운영/기준 모델로 유지된다. 코드3파일·버전 안내는 이전 계약으로 되돌릴 수 있지만 합성 방어도 제거된다. 마그마 라벨은 사용자 저장 원본과 `before-area-confirmation-20261015.jsonl` 백업을 구분해 보존한다. Recall 격리 사본은 원위치 복구 가능하지만 선별 기준을 충족하기 전에는 학습에 쓰지 않는다. 호출 기록은 삭제하지 않는다.
