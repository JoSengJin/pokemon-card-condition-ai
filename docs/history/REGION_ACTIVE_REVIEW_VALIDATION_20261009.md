## 현재 저장 데이터에서 확인된 빈틈

입력 `data/learn-review.jsonl`, 모델 `artifacts/region-baseline-20261009-efficient-epochs20/model.pt` 사용.

train의 명시적 정상 구역을 가진 실물 수:

|면|모서리|엣지|표면|
|---|---:|---:|---:|
|앞면|4|4|4|
|뒷면|0|0|0|

뒷면 정상 자료 부족은 확인된 사실이다. 이것만으로 뒷면 오탐의 원인을 확정하지 않는다. 후보468개 중 아래3개 실물/구역만 요청한다. 전체 재라벨링은 필요 없다.

|실물|면|구역|확인 항목|
|---|---|---|---|
|v|뒷면|우측 하단|표면 결함|
|y|뒷면|좌측 하단|표면 결함|
|ebay-50f5e8124d55bb|뒷면|우측 상단|엣지 결함|

산출물 `artifacts/region-review-plan-20261009-links.json`에 정확한 이미지 경로·픽셀 해시·카드 영역·모델 출력·바로가기 query 보존. 앞선 `...uncertainty.json`은 같은 선택의 링크 추가 전 기록이다. 모델 출력은 보정된 신뢰도가 아니며 정답이나 결함 근거로 사용하지 않는다.

## 사람 확인 방법과 다음 순서

각 후보에서 충분히 보이면 해당 구역의 실제 상태를0/1로 기록하고 저장한다. 실제 결함이 보이면 면별 같은 결함도1로 확인한다. 반사·흐림 등으로 확인하기 어려우면 미확인 유지 및 사유/위치를 기록한다. 빨간 안내선은 손상으로 라벨링하지 않는다. 미확인으로 남기는 것도 유효하며 억지로 정상 정답을 만들지 않는다.

v의 실제 화면을 열고 뒷면 우측 하단 확대와 표면 입력칸 자동 초점을 확인했다. 저장 버튼은 비활성으로 사람이 입력하기 전 서버 라벨이 변경되지 않았다. 서버 재시작 없이 새 HTML 적용.

사람 확인 후 새 snapshot을 고정하고 기존과 같은 train/val·설정으로 보강 전후 비교한다. 새 라벨로 자동 재학습하지 않으며 결과가 좋다고 곧바로 운영 적용하지 않는다. 신규 독립 최종평가는 별도 과제다.

## 검증 / 한계 / 롤백

Python 전체38개와 리뷰 JS 회귀검사 통과. 후보 추출은 실제 저장 데이터에서 실행했고 화면의 확대 구역과 초점을 실제 브라우저로 확인했다. 원본 사진/라벨/모델 가중치 변경 없음. 현재 Gemini 절감0건.

0.4.4 wheel 빌드 완료, region_review_plan/cli/review.html이 소스와 바이트 단위 일치. SHA256 `d2a3bf28bd2451a2cb477f46cae1f55e6a3abe6b9128e0f6d70fb410c630eb5d`. 새 가상환경 설치 검증은 하지 않았다.

이 방법은 정상 보강 목적의 제한된 능동 표본 추출이다. 임의의 미확인 구역이나 새 카드 전체를 자동 라벨링하는 방식이 아니다. train 출력의 애매함이 일반화 오류를 뜻하지 않으며, 알려진 모델 편향과 서로 비슷한 사진에 선택이 몰릴 수 있다. 같은 실물 그룹 구분은 사람 입력의 정확성에 의존한다. URL은 사진 경로 변경을 검사하지만 파일 내용이 같은 경로에서 교체되는 상황까지 해시 검사하지 않는다. 최종평가 누수 방지에는 기존 evaluator의 해시 검사를 사용한다.

롤백: `region-review-plan`을 사용하지 않고 일반 라벨 화면 URL로 접속하면 기존 수동 작업을 계속할 수 있다. 소스 전체 롤백은 위 기능 diff만 되돌리고0.4.3 wheel 사용. 생성된 plan은 읽기 전용 기록으로 보관 가능하다.
